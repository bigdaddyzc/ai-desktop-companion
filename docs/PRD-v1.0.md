## 0. 阅读说明与决策状态

本文是一份完整的产品需求方案，不是已经通过验证的硬件规格书，也不表示全部建议均已得到用户批准。

### 0.1 用户已确认的方向

1. 做一个兼具好玩与实用价值、最终能够成为真正产品的 AI 桌面伙伴。
2. 硬件设计参照 **ESP32-S3-DevKitC-1**，不改用其他开发套件作为基准。
3. 用户尚无 ESP32 开发经验，希望先体验效果，暂不购买硬件。
4. 模拟器以桌面小宠物的形式存在，并尽可能对应未来实体设备。
5. 应用覆盖编码、设计、文档办公及娱乐。
6. 高度重视外观、交互和行为与真机的一致性。

### 0.2 本方案建议采用的默认决策

以下是可执行的建议，不是新增的已确认事实：

- 首先交付 Windows 桌面体验版，再接入真实工作事件，最后验证实体硬件。
- 采用“开发板＋外接小屏幕＋外接业务按钮”的设备组合；不将扩展屏幕画成板载元件。
- 建议屏幕逻辑分辨率为 240×240，显示驱动候选为 SPI ST7789；最终模块、尺寸和接口需验证。
- 首版使用 USB 供电，不设计电池、移动底盘、机械臂或舵机。
- 第一条深度工作集成优先选择 VS Code 与本地命令任务；其他软件先通过手动会话和明确授权的内容输入覆盖。
- 即时行为由本地状态机控制，AI 负责意图理解、解释和总结，不控制每一次动画。
- 桌面版与实体版共用消息协议、资源和尽可能多的设备 UI／业务逻辑，平台驱动分别实现。
- 首版以文字交互为主；录音、语音识别、语音合成和实体音频链路分阶段加入。

### 0.3 关于“完美复刻”的需求解释

将“完美复刻”拆成可以检验的要求：

- **外观对应：** 按选定板卡及扩展件的真实结构建模，不虚构板载功能。
- **软件行为对应：** 同样的规范化输入，在规定测试范围内产生相同的业务状态和设备反馈。
- **屏幕内容对应：** 尽可能共用渲染实现、逻辑分辨率、字体、图片和动画。
- **通信对应：** 模拟设备和实体设备使用同一套有版本号的消息协议。
- **差异透明：** 桌面专属功能、模拟输入和未验证项目必须明确标注。

**不承诺完全复现电气特性、真实音质、拾音、显示面板观感、功耗、热行为、无线干扰、机械手感或全部芯片指令行为。** 这些不应被“高保真”字样掩盖。

## 1. 产品概述

### 1.1 一句话定位

一只以真实 ESP32-S3 硬件结构为基础、能理解工作上下文并提供克制陪伴的桌面伙伴；先以软件形式使用，后续可以在实体小设备上延续同样的核心体验。

### 1.2 产品的三个组成部分

1. **桌面伙伴客户端：** 用户每天实际使用的透明桌面窗口、控制面板、提醒与互动入口。
2. **电脑桥接服务：** 接收工作软件事件、管理任务和上下文，并连接 AI 与设备。
3. **设备模拟／实体终端：** 用一致的协议呈现表情、短文本、计时和工作状态。

桌面版本不是一次性演示。即使用户始终不购买硬件，它也应具备独立使用价值。

### 1.3 核心价值

- **感知进展：** 不反复切回终端，也能知道任务是否结束、是否需要自己处理。
- **减少操作：** 用简单自然语言或两三个操作创建计时、待办和工作会话。
- **陪伴而不干扰：** 工作时安静，完成时回应，休息时可互动。
- **先验证再投入：** 在买硬件之前验证产品价值和交互方案。
- **可迁移：** 将来接入实体设备时不重做整套产品逻辑。

## 2. 目标、非目标与产品原则

### 2.1 产品目标

| 编号 | 目标 | 判断方式 |
|---|---|---|
| G-01 | 无硬件也能完整体验核心功能 | 安装后可使用专注、待办、互动、事件演示和模拟测试 |
| G-02 | 接入至少一条真实工作事件链路 | 能展示实际任务的开始、结束、失败和等待确认状态 |
| G-03 | 覆盖编码、设计、文档、娱乐四类场景 | 每类均有可用流程，不把“手动覆盖”描述成“自动集成” |
| G-04 | 建立可验证的模拟／实体一致性 | 有硬件画像、协议、回放用例和差异清单 |
| G-05 | 成为可持续使用的日常产品 | 不抢焦点、不持续发声、可暂停、可关闭、可恢复工作状态 |
| G-06 | 降低新手硬件入门门槛 | 分阶段验证，明确扩展件、接线职责和未验证事项 |

### 2.2 首版非目标

- 从零开发支持全部外设与指令集的 ESP32 芯片模拟器。
- 承诺与真机在所有物理指标上完全一致。
- 自动读取任何软件的全部工作内容。
- 持续截屏、全局键盘记录、静默开启麦克风。
- 通过应用前台时长判断生产力、心理状态或工作质量。
- 自动点击任意软件、任意执行终端命令、自动发送消息。
- 对用户进行员工式监控、排名或绩效评分。
- 首版量产自研 PCB、设计电池或增加复杂机械结构。
- 将云端大语言模型运行在 ESP32-S3 本机上。
- 游戏内注入、读取游戏内存、绕过反作弊或自动操作游戏。

### 2.3 产品原则

1. **真实优先于拟人化：** 不编造工作进度，不把演示台词冒充 AI。
2. **本地优先：** 无需云端的能力留在本地，断网仍能计时与互动。
3. **事件优先于猜测：** 有明确事件才显示明确状态。
4. **有限动作优先于自由执行：** AI 只能请求允许的业务动作。
5. **用户控制优先：** 通知、记忆、上下文分享、启动项均可控制。
6. **可爱不等于打扰：** 没有惩罚性养成、愧疚话术或强迫互动。
7. **产品 UI 与开发工具分离：** 日常简洁，调试信息按需展开。

## 3. 用户画像与关键场景

### 3.1 主要用户

- 独立开发者、学生或个人创作者，经常同时使用 IDE、浏览器、设计工具和办公软件。
- 对硬件感兴趣但不熟悉接线、固件和电源设计，希望先从软件体验开始。
- 希望获得状态提醒和陪伴，但不愿让一个助手持续监控电脑。

### 3.2 编码场景

用户启动测试后切到其他窗口。伙伴显示“测试中”；测试工具返回结果后显示“完成：18/20，通过 18 项，失败 2 项”。没有总数时只显示阶段，不显示百分比。用户点击伙伴查看详情，再主动选择是否让 AI 分析已授权的日志。

### 3.3 设计场景

用户创建“首页设计”会话并进入安静模式。阶段结束时主动分享一张导出的设计图，AI 结合用户目标给出反馈。若安装设计工具插件，可增加插件自身操作的开始和完成事件；不假设能监听所有原生操作。

### 3.4 文档办公场景

用户说“记录一个待办，明天下午完善方案”。伙伴给出可编辑草稿；存在日期或时间歧义时要求确认。用户主动粘贴选中文本后，可请求摘要或改写；默认不扫描打开的文档。

### 3.5 娱乐场景

用户切换休息模式，伙伴播放短动画，支持摸头、简单反应小游戏和轻量聊天。用户进入全屏游戏时，按配置隐藏或静音，不遮挡操作。

### 3.6 硬件预体验场景

用户在模拟器中点击按钮、断开网络、恢复连接，观察同一设备 UI 的表现，并查看输入事件与状态转换。界面持续标识当前为“模拟设备”，不让演示状态混入真实工作状态。

## 4. 产品形态与硬件基线

### 4.1 硬件基准

固定采用 **ESP32-S3-DevKitC-1**。在进入精确外观建模及固件开发前，必须进一步锁定：

- 板卡硬件修订版本及对应官方资料。
- 模组完整料号、Flash 与 PSRAM 容量。
- 天线形式、USB 接口布局、板载按钮、引脚排针和指示灯细节。
- 是否采用官方板或明确来源的兼容板。兼容板不能自动视为尺寸、颜色与布局完全相同。

建议评估带 PSRAM 的模组版本，例如名称含 N8R8 的配置，但**此项不是已核验的采购指定**。容量、引脚占用和目标软件兼容性必须经过选型检查。

### 4.2 板载能力与扩展能力边界

| 能力 | 来源 | 需求约束 |
|---|---|---|
| ESP32-S3 主控、USB、引脚扩展 | 基准开发板 | 以锁定版本资料为准 |
| 板载状态指示灯 | 基准开发板的具体版本 | 固件实现前核对类型和引脚，不在 PRD 中猜测 |
| 宠物表情与文字屏幕 | **外接显示模块** | 不得画成基准开发板自带屏幕 |
| 业务确认／返回按钮 | **外接业务按钮** | 不默认占用板载 BOOT 或 RESET 按钮 |
| 麦克风 | 后续外接音频模块 | 首版不依赖 |
| 扬声器、功放 | 后续外接音频模块 | 电脑播放声音不等于已验证实体播放链路 |
| 光照、温湿度等环境感知 | 可选扩展传感器 | 没有硬件时只能标为模拟输入 |
| 电池与充电管理 | 非基准开发板默认产品能力 | 首版不纳入 |

### 4.3 建议的首版参考装配

- ESP32-S3-DevKitC-1 × 1。
- SPI 小屏幕 × 1，逻辑分辨率暂定 240×240。
- 外接业务按钮 × 2：确认／互动、返回／静音。
- USB 供电和必要的连接件。
- 开放式或透明支架，使开发板与外接屏幕的关系清晰可见。

首版不要求触摸屏。若后续选用触摸模块，需要新增硬件画像，不将普通屏幕的点击区域直接宣称为真机触摸能力。

### 4.4 外观复刻要求

- 根据选定版本资料建立可追溯的外观参考包，包含来源、版本、日期和尺寸基准。
- 不凭记忆填写板卡精确长宽、孔位或引脚间距。
- 天线区、接口、BOOT／RESET、排针和屏幕必须处于真实可装配的位置。
- 不把宠物的眼睛贴在天线或芯片表面，冒充具有显示能力的实体区域。
- 若使用自定义支架，必须标注“拟议产品支架”，与板卡原有结构区分。
- 显示器 DPI 会影响屏幕上的物理尺寸；默认承诺尺寸比例正确，不承诺任何电脑上都自动呈现毫米级 1:1 尺寸。
- 准确色彩、表面材质与发光效果在取得实物后校准。

### 4.5 三种显示视图

1. **日常伙伴视图：** 外观为开发板与外接屏幕组成的装配体，主要交互发生在屏幕和业务按钮上。
2. **硬件检查视图：** 放大查看板卡、扩展件、接口和映射关系，可显示标注。
3. **开发面板：** 查看事件、状态、指令、模拟条件与回放结果，不属于实体设备屏幕。

窗口拖动、跨显示器移动、系统托盘和电脑快捷键属于桌面专属能力。实体设备不具备自主移动能力，首版不设计整个设备在桌面行走的动画。

## 5. 功能范围与优先级

### 5.1 优先级定义

- **P0：** 桌面体验版和核心流程必须具备。
- **P1：** 工作增强和产品化阶段加入；某些项目是实体版发布的前置条件。
- **P2：** 后续扩展，不阻塞首版。

优先级不代表已承诺上线日期。实体版的硬件安全、身份认证和实机验收不能因为列在后续阶段而被跳过。

### 5.2 范围总表

| 模块 | P0 | P1 | P2 |
|---|---|---|---|
| 桌面载体 | 透明窗口、拖动、托盘、基本设置 | 安装升级、完整多屏适配、设备切换 | 其他操作系统 |
| 设备表现 | 对应开发板及外接屏幕、基础表情 | 按最终参考资料校准外观 | 更多真实硬件画像 |
| 工作会话 | 编码／设计／文档／娱乐手动切换 | 应用适配、会话总结 | 跨设备会话 |
| 编码集成 | 本地任务包装器、开始与结束状态 | VS Code 插件、AI 工具公开 hooks | 更多 IDE／CI |
| 设计集成 | 手动会话、主动提交设计图 | 一个经验证的设计工具插件 | 更多设计软件 |
| 文档办公 | 快速待办、手动提交选中文本 | 文档插件、日历集成 | 复杂办公自动化 |
| AI | 明确的演示模式、真实接口接入路径 | 授权后连接一个真实提供方并完成回归 | 可选本地推理等部署方式 |
| 娱乐 | 摸头、休息动画、反应小游戏 | 可配置性格、更多轻量玩法 | 分享及创作内容 |
| 模拟测试 | 输入注入、断网、延迟、事件回放 | 固件测试接口、实体对照测试 | 更广泛外设仿真 |
| 音频 | 默认无录音；可选桌面提示音 | 按键录音／语音回复及硬件音频验证 | 唤醒词等常驻语音能力 |
| 隐私安全 | 本地存储、内容授权、清除数据 | 设备配对、公开分发所需安全基线 | 可选云同步 |

**桌面体验版允许未配置真实 AI，但必须明确显示“演示模式”，不能作为已完成 AI 能力验收。** “AI 桌面产品版”发布前，真实接口、费用提示、取消和失败处理必须通过独立验收。

## 6. 详细功能需求

### F-01 桌面窗口与生命周期（P0）

- 伙伴以无多余窗框的桌面小窗口存在，支持透明背景。
- 支持拖动、缩放、置顶开关、隐藏、显示和退出。
- 默认不抢键盘焦点，不因提醒突然切走用户正在使用的软件。
- 可配置透明区域点击穿透；设备交互区域必须保持可操作。
- 托盘菜单至少包含显示伙伴、控制面板、勿扰、退出。
- 关闭窗口默认隐藏至托盘；首次发生时说明，设置中可改为退出。
- 开机自启动默认关闭，用户主动开启。
- 窗口位置按显示器工作区保存，显示器移除后自动回到可见区域。

**验收：** 隐藏后可从托盘恢复；全屏任务不被抢焦点；更换显示器后不会出现无法找回的窗口。

### F-02 宠物表现与角色（P0）

至少提供以下设备屏幕状态：待机、专注、任务进行中、等待用户、成功、失败提示、休息、AI 等待、连接异常、睡眠。

- 待机采用低频眨眼、轻微视线变化，不持续高速动画。
- 表情、文字、声音和业务状态分离，换皮肤不能改变任务事实。
- 提供至少一种基础性格；性格影响用词和表现，不改变权限和安全规则。
- 不声称通过摄像头、声音或工作时长判断用户的情绪。
- 提供减少动画和静音选项，不仅靠颜色传达状态。

**验收：** 相同业务状态在不同性格下仍表达相同事实；关闭动画后关键状态仍可识别。

### F-03 输入与实体映射（P0）

- 模拟器中点击业务按钮，对应同编号实体按钮事件。
- 首版普通屏幕上的点击仅用于桌面详情／展开，除非硬件画像明确具备触摸屏；此区别必须可见。
- 确认按钮短按：确认当前明确提示，或在无提示时触发互动。
- 返回按钮短按：返回上一设备页面；长按：切换静音／勿扰的预定义行为。
- 长按阈值、按键去抖和重复触发策略在交互规格中固定，建议起点为长按 800ms，最终通过原型验证。
- 板载 BOOT／RESET 在硬件检查视图中保持其真实用途，不冒充默认业务按钮。
- 录音等需要持续授权的功能应有独立输入说明，不能复用一个含糊手势偷偷开启。

**验收：** 输入映射表可导出；同一回放中桌面与设备状态转换一致；不会因一次长按又触发短按造成重复操作。

### F-04 工作会话（P0）

- 支持编码、设计、文档办公、娱乐四类会话，以及未分类会话。
- 会话包含名称、类别、开始时间、暂停时间、可选目标和相关任务。
- 手动启动会话无需安装任何集成插件。
- 活跃会话可以切换；后台任务独立存在，不因切换前台工作而被标为结束。
- 自动应用识别为可选增强，默认关闭，不据此评估工作质量。

**验收：** 编码测试在后台运行时切换到文档会话，测试结果仍关联原任务并正常提醒。

### F-05 专注与休息（P0）

- 支持预设和自定义计时、暂停、继续、取消。
- 区分“计时结束”和“任务完成”，不会自动把待办标记为完成。
- 勿扰期间以屏幕状态为主，声音和系统通知按用户规则处理。
- 程序重启后显示可恢复的计时；用户选择继续、结束或重新开始。
- 系统休眠、时区变化和系统时间调整不能造成反复到时通知。
- 同一计时完成事件在桌面与实体终端之间去重，默认只由一个选定终端发声。

**验收：** 在断网、重启、休眠恢复、重复事件回放下，不重复创建计时或重复通知。

### F-06 快速记录与待办（P0）

- 支持手动输入；真实 AI 启用后支持将自然语言整理为草稿。
- 草稿可以修改名称、日期、时间和提醒方式。
- “下午”“下班前”等缺少明确时间的说法必须确认，不能静默替用户决定。
- 本地保存成功后才显示“已记录”。
- 支持完成、撤销、删除和导出。
- 删除全部记录或批量清除必须二次确认。
- 用户未启用系统通知权限时，应解释提醒将仅在产品内显示。

### F-07 工作事件卡片（P0）

设备屏幕优先展示：任务短名称、明确状态、可信进度、是否需要处理。

- 仅知道开始／结束：显示“进行中”，不显示百分比。
- 知道完成数和总数：显示数量，必要时再计算百分比。
- 数据停止更新：显示“状态待确认”或“连接中断”，不能当成失败或成功。
- 完整日志在电脑详情面板中查看，不挤进小屏幕。
- 失败原因可以是工具原文摘要；AI 解释需要单独标记。

### F-08 AI 对话与有限动作（P1，AI 产品版必需）

- 支持文字输入、流式展示、取消生成和重试。
- 真实模式显示已连接的提供方／部署类型；未配置时显示明确的演示标识。
- 演示模式不得自行调用付费接口，也不得伪装成已读取真实文件。
- AI 可请求的动作限于：创建计时草稿、创建待办草稿、查询已授权任务状态、切换产品内模式、请求展示表情、解释已授权内容。
- AI 不能任意执行 shell、点击外部软件、删除文件、发送邮件或关闭进程。
- 所有动作参数经过结构校验、业务权限检查和数值范围检查。
- 系统拒绝非法动作时，仍保留可读解释，不产生部分执行的含糊状态。
- API 凭据保存在电脑侧受保护存储，不写入设备固件、日志或导出文件。
- 配置真实服务前提示费用、联网需求和数据发送范围。
- 模型不可用时不影响基本表情、计时、待办和已接入工作事件。

### F-09 上下文分享（P0 手动，P1 增强）

- 用户通过粘贴文本、选择日志片段、选择文件或主动截图提供上下文。
- 分享前预览实际发送内容，显示来源、范围和目的。
- 不默认发送完整仓库、整个桌面或整个设计文档。
- 超过大小限制时提示选择范围或显式摘要，不能静默截断后假装已经读完。
- 日志与文档中的“指令”按内容处理，不得覆盖系统权限或自动触发动作。
- 第三方 AI 服务的数据保留政策需在配置界面说明，不能承诺自己无法控制的远端立即删除。

### F-10 娱乐与轻量陪伴（P0）

- 摸头／互动按钮触发短反馈。
- 提供休息动画与一个简单反应小游戏，使用小屏幕和业务按钮即可完成核心玩法。
- 娱乐不得占用工作异常和明确待处理事项的永久展示位置。
- 不使用掉血、饥饿惩罚、连续签到损失等机制逼迫互动。
- 游戏／会议期间按设置静音、隐藏或保持静态。
- 桌面提示音可以在用户交互后开启；不把电脑音响效果宣传为实体音质。

### F-11 勿扰与提醒策略（P0）

- 支持手动勿扰、定时勿扰和用户配置的全屏策略。
- 提醒分为需用户处理、任务结果、普通互动三类。
- 默认不弹出大窗口、不抢焦点。
- 相同结果合并提醒，短时间多个成功事件可汇总为一条。
- 勿扰期间记录结果，结束后提供摘要，而不是补播全部声音。
- 需要确认的任务可以保留状态标识，但是否发声由用户配置。

### F-12 模拟器控制与回放（P0）

开发面板支持：

- 注入短按、长按、模拟传感器值和规范化工作事件。
- 切换 AI 演示／真实模式，并明确提示是否会产生费用。
- 模拟设备断线、桥接服务断线、AI 不可用和消息延迟，四者不能混为一个开关。
- 注入重复、乱序和过期事件。
- 保存和回放测试序列；指定动画随机种子和测试时间。
- 查看输入、状态转换、输出指令与错误。
- 导出脱敏的测试记录和差异报告。

模拟事件带有独立命名空间和 simulation 标识，默认不写入真实工作统计，也不修改真实待办。

### F-13 设置与数据管理（P0）

设置至少包含外观尺寸、置顶、声音、动画、勿扰、启动项、显示模式、数据保留、AI 连接、已授权集成和清除数据。

- 提供恢复默认设置，不顺带删除任务。
- 提供单独的任务导出与配置导出，均不含密钥。
- 提供“清除全部本地数据”，列出影响范围并要求确认。
- 不要求注册产品账号才能使用本地功能。

## 7. 工作集成方案与能力边界

### 7.1 分级接入

| 等级 | 接入方式 | 能力 | 不能宣称 |
|---|---|---|---|
| L0 | 手动会话／主动内容分享 | 所有工作类别均可使用 | 自动理解全部应用状态 |
| L1 | 命令包装器或结构化输出 | 可靠获得任务生命周期 | 任意命令都有细粒度进度 |
| L2 | 官方插件 API／公开 hooks | 获得该接口明确提供的事件 | 观察软件所有内部行为 |
| L3 | 额外授权的应用／系统能力 | 特定窗口、选区或前台元数据 | 无授权持续监控或完美语义识别 |

每个适配器在 UI 中显示其实际能力，例如“仅手动”“可接收任务结果”“可读取用户选中内容”。

### 7.2 编码

**P0：本地任务包装器**

- 用户主动通过包装器启动允许的开发命令。
- 接收进程开始、退出码、取消状态和可选结构化进度。
- 日志保留在本地；分享给 AI 前让用户选择。
- 用户关闭终端或包装器失联时显示未知状态，不假设成功。

**P1：VS Code 插件与公开 AI 工具事件**

- 使用正式插件接口获取任务、调试或用户主动分享的上下文。
- 编辑行为只用于用户授权的会话状态，不默认收集编辑内容。
- AI 工具只有在提供明确 hook／事件时，才接入开始、结束、等待确认等状态。
- 不通过抓取工具内部私有协议或猜测窗口文字来伪造可靠集成。

### 7.3 设计

**P0：** 会话、专注、待办、主动提交图片与设计目标。

**P1 候选：** Figma 或用户主要使用的设计工具。选型前验证插件是否能提供目标事件。

- 插件可以报告自己发起的导出／检查操作，以及用户主动分享的选区。
- 不保证能长期后台运行或监听所有原生导出。
- 无法自动观察的场景保留明确的手动操作入口。
- 图片分析与设计建议属于 AI 输出，不视为确定的可用性结论。

### 7.4 文档办公

**P0：** 手动文档会话、快速记录、主动粘贴文本、摘要或改写请求。

**P1 候选：** 用户主要办公套件的公开扩展接口。

- 不预设 Word、WPS、浏览器文档具有相同 API。
- 文档打开、保存、选区和修订事件需逐项验证。
- “保存成功”必须来自明确结果，不根据文件名、窗口停留时间或定时器猜测。
- 写回原文档、发送消息、日历创建等属于额外权限与确认流程，不随只读集成自动开启。

### 7.5 娱乐与媒体

- 首版采用用户手动切换娱乐模式。
- 可选的全屏／前台应用识别仅使用完成该功能必要的元数据，并由用户开启。
- 播放状态集成以公开媒体接口为前提，不能默认所有播放器都支持。
- 不需要管理员权限，不注入游戏进程。

## 8. 状态模型、事件与优先级

### 8.1 状态必须分维度管理

不能用单个“忙碌／离线”变量表达所有情况。

| 维度 | 示例 |
|---|---|
| 用户会话 | 未开始、编码、设计、文档、娱乐、暂停 |
| 任务状态 | 排队、运行、等待用户、成功、失败、取消、未知 |
| 计时状态 | 未开始、计时、暂停、到时、取消 |
| AI 状态 | 未配置、演示、请求中、完成、失败、取消 |
| 连接状态 | 桌面桥接、各适配器、实体设备分别记录 |
| 表现状态 | 待机、专注、庆祝、提醒、休息、睡眠 |

例如“AI 正在生成总结”不代表测试仍在运行；“实体设备断线”不代表电脑没有网络。

### 8.2 展示仲裁规则

默认优先顺序：

1. 当前需要用户确认的事项。
2. 用户关注任务的失败或关键异常。
3. 计时到时。
4. 最近的任务成功结果。
5. 当前专注／工作状态。
6. 娱乐或待机表现。

此顺序决定屏幕展示，不直接决定是否发声；通知还需经过勿扰策略。短暂展示结束后，恢复仍有效的主状态。用户可以选择固定关注某个任务。

### 8.3 规范化事件要求

每个事件至少包含：

- event_id：用于去重的唯一标识。
- source_id：来源适配器或设备。
- session_id、task_id：适用时关联会话与任务。
- source_seq：来源能提供时使用的递增序号。
- occurred_at：来源发生时间。
- received_at：桥接服务接收时间。
- event_type：明确的事件类型。
- payload：按类型约束的内容。
- simulation：是否模拟数据。
- privacy_level：元数据、用户内容等分类。
- schema_version：消息格式版本。

进度字段允许为未知，不允许把缺失值补成虚构百分比。跨来源顺序不能只根据电脑时间戳臆测。

### 8.4 断线、重复与乱序

- 相同 event_id 不产生第二次业务副作用。
- 已结束任务不能被旧的 running 事件退回进行中。
- 只有明确的新任务／重试实例才可重新开始。
- 长任务来源应有存活检查；无更新且来源不可确认时显示未知，不自动失败。
- 支持心跳的适配器建议初始配置为 30 秒一次，连续 90 秒无响应标记来源异常；具体参数通过实际测试调整。
- 重连后优先获取当前快照，再继续增量事件。
- 模拟与真实来源分区，避免回放污染真实状态。

## 9. 模拟与真机一致性方案

### 9.1 共用层与分离层

**应共用或由同一规范生成：**

- 设备能力画像。
- 消息协议、动作枚举和错误码。
- 设备页面定义、字体、图片和动画资源。
- 任务展示、计时和交互状态机。
- 事件回放、输入输出期望和界面基准样本。

**必须分开实现并测试：**

- 桌面窗口、系统托盘与电脑通知。
- ESP32 的 GPIO、SPI、音频、USB 和无线驱动。
- 电脑与实体设备的输入、存储和时钟适配。
- 供电、按键电路、音频电路和真实面板。

共用代码比例属于技术验证结果，不在 PRD 中承诺任意百分比。

### 9.2 UI 实现建议

建议技术验证 **LVGL 在 ESP32 与桌面原生／WASM 环境中共用设备 UI** 的可行性。

- 设备显示区域采用同一逻辑分辨率、字体集和像素格式。
- 桌面放大只是显示缩放，不改变设备 UI 的排版。
- 丰富聊天历史、配置和日志放在电脑控制面板，不塞入设备模拟屏幕。
- 如果第一阶段使用网页临时渲染，必须标为“体验原型”；不能将它的截图通过视为已完成固件 UI 一致性验证。
- 具体桌面框架、UI 编译路径和固件工程在技术设计阶段确定；以一致性、维护成本和资源测试结果选型。

### 9.3 一致性分级

| 级别 | 定义 | 所需证据 |
|---|---|---|
| C0 外观概念 | 按资料制作的设备外形 | 参考资料、拟议外设说明 |
| C1 产品交互 | 可操作的设备页面和状态流程 | 场景测试、回放结果 |
| C2 软件一致性 | 共享实现或受约束实现产生一致状态／屏幕输出 | 固定输入、状态轨迹、显示缓冲对照 |
| C3 实机验证 | 指定硬件版本上通过核心测试 | 固件版本、实机记录、差异清单 |
| C4 物理校准 | 对显示、声音、延迟、功耗等进行测量 | 仪器／实测记录与容差 |

任何发布页面都只能声明已经达到的级别。C1 不能宣传成 C3，C3 也不代表所有物理指标完全相同。

### 9.4 一致性验收方法

- 固定测试时钟、输入序列、随机种子和动画采样位置。
- 对有限的基准用例比较状态转换，不用肉眼相似替代逻辑验证。
- 对显示缓冲比较文字、图标、布局和像素差异；面板的真实颜色与电脑屏幕分别评估。
- 若采用完全相同的确定性渲染路径，目标是基准样本显示缓冲一致；若不能一致，必须解释差异并事先制定容差，不能测试后放宽以获得通过。
- 用 GPIO／按键／网络实测验证实体输入映射，不以鼠标可点击替代接线正确性。
- 未实现的外设返回“不支持”，不伪造成功响应。

## 10. 信息架构与界面要求

### 10.1 伙伴小窗口

展示顺序：设备屏幕、业务按钮、必要连接标识。日常默认不显示日志、调试编号或大量状态小组件。

设备屏幕建议包含：

- 表情区域。
- 一条简短主状态。
- 按需展示的任务名称或计时。
- 必要的小型状态标识。

小屏幕不承担长文阅读。中文文本需要明确截断、换行、分页和缺字策略，不默认无限滚动跑马灯。

### 10.2 电脑控制面板

- **概览：** 当前会话、关注任务、待办、计时。
- **对话：** 真实／演示模式标识、输入、上下文预览、取消。
- **集成：** 适配器列表、权限、连接状态、能力与最近更新时间。
- **设备：** 硬件画像、模拟／实体选择、连接与差异说明。
- **测试：** 模拟条件、事件回放、结果导出。
- **设置：** 外观、通知、隐私、数据和启动项。

### 10.3 必须存在的界面状态

首次启动、无任务、无真实 AI、无适配器、适配器失联、AI 超时、无权限、保存失败、设备断线、恢复连接、未知进度、正在取消、取消完成。

### 10.4 可访问性

- 电脑面板支持键盘操作、明确焦点和屏幕阅读器可识别的控件名称。
- 状态不只靠红绿区分。
- 支持文字大小与减少动画。
- 限制闪烁，不使用强烈高频闪屏作为失败提醒。
- 多显示器和 100%／150%／200% 缩放下控件可用。

## 11. AI 行为与安全约束

### 11.1 AI 负责什么

- 理解用户表达并生成结构化草稿。
- 解释已经提供的状态或内容。
- 给出简短、可选的工作建议。
- 在用户发起时聊天、总结或生成娱乐内容。

### 11.2 AI 不负责什么

- 判定底层按钮是否按下。
- 决定任务实际上是否成功。
- 执行实时屏幕刷新。
- 无授权收集电脑上下文。
- 绕过校验直接操作设备或文件系统。

### 11.3 动作执行链

AI 请求 → 格式校验 → 权限校验 → 必要确认 → 业务执行 → 真实执行结果 → 用户反馈。

- 模型说“已完成”不等于操作完成，必须有业务层成功结果。
- 用户取消后，尚未提交的动作不得继续执行。
- 已发生的本地操作应回报事实，不用“取消”掩盖已经产生的副作用。
- 无法解析的输出不能作为设备指令使用。
- 设备只接受允许的动作和资源标识，不接收任意脚本。
- AI 输出不能直接决定不受限的蜂鸣时长、显示闪烁频率或 GPIO 操作。

### 11.4 成本和服务异常

- 真实服务配置需用户明确授权。
- 显示请求状态、可取消操作和基本用量信息；没有可靠计费数据时不显示伪精确费用。
- 不为普通眨眼、计时和每条事件调用模型。
- 不自动使用未知的付费回退提供方。
- 网络／服务错误采用有上限的重试，取消后停止重试。
- 外部 AI 总时延单独测量，不计入本地 UI 即时反馈承诺。

## 12. 数据、隐私与权限

### 12.1 主要数据对象

| 对象 | 核心内容 | 默认保存策略 |
|---|---|---|
| 设置 | 外观、通知、集成开关 | 本地保存，直到用户修改／清除 |
| 任务与待办 | 名称、状态、时间、提醒 | 本地持久化，支持删除／导出 |
| 工作会话 | 类别、起止、关联任务 | 本地保存；保留期限可配置 |
| 事件审计 | 来源、类型、状态、错误码 | 默认保留 7 天，不含完整文档或日志正文 |
| 聊天内容 | 当前对话和主动输入 | 默认不跨应用会话长期保存，用户可主动保存 |
| 内容附件 | 用户选择的文本／图片 | 按请求需要临时处理；持久保存需明确操作 |
| AI 凭据 | 访问密钥等 | 操作系统受保护凭据存储，不参与导出 |
| 设备配对信息 | 设备身份与连接权限 | 本地受保护保存，可撤销 |

如启用云服务，发送与保留规则还受该服务政策影响，界面必须明确说明本地删除和远端删除不是同一回事。

### 12.2 权限原则

- 本地基本功能无需管理员权限。
- 应用状态、内容分享、麦克风和云端请求分别授权。
- 默认不启用遥测；若后续引入匿名产品指标，需明确开关与收集说明。
- 适配器卸载／禁用后停止收集。
- 对外接口仅暴露必要能力；本机桥接接口也需要防止其他网页或应用未经授权调用。
- 局域网设备连接必须在真实硬件接入阶段完成配对、身份认证和安全传输设计，不能裸露匿名控制端口。
- 日志不得包含密钥、完整认证头或默认收集的用户文档。

### 12.3 产品伦理

- 不将用户的工作内容用于默认训练。
- 不用忙碌时长、键盘事件等推导绩效排名。
- 不制造“你不陪我我就难过”的压力。
- 不把伙伴包装成具备真实感情或医疗判断能力的实体。
- 提醒和总结为辅助，用户始终可以忽略、暂停或关闭。

## 13. 离线、恢复与一致性

### 13.1 离线能力

没有互联网时，桌面仍能：显示表情、运行计时、管理本地待办、接收本地适配器事件、进行本地互动和回放。

AI 不可用时显示明确状态，不阻塞其他模块。

### 13.2 实体端离线原则

- 实体设备与电脑断开后，不继续展示为“工作状态实时更新”。
- 显示最后同步时间或明确的断线标识。
- 已接受的本地计时可以继续，但完成事件在重连后去重。
- 涉及修改中心任务状态的离线输入，要么明确提示不可用，要么进入可见的待同步队列；不能静默假装保存成功。
- 首版实体实现优先选择“断线时禁止修改中心任务”，降低冲突复杂度。

### 13.3 时钟与恢复

- 活跃计时使用适合经过时间测量的时钟，不依赖持续刷新数字累加。
- 持久化保存恢复所需时间点和状态。
- 重启、休眠或时钟跳变后执行一次恢复判定，避免重复通知。
- 多终端计时以电脑服务记录为主要业务事实来源，并保留设备端已接受计时的离线执行状态。

## 14. 非功能需求

以下数字是**待验证的验收目标，不是已经测得的性能**。技术设计阶段应固定测试电脑、系统版本、应用版本和负载。

| 类别 | 建议目标／要求 |
|---|---|
| 本地输入反馈 | 按钮／鼠标输入至可见反馈 p95 ≤ 150ms，不包含 AI 生成 |
| 本地事件展示 | 桥接服务收到有效事件至桌面状态更新 p95 ≤ 300ms |
| 适配器端到端时延 | 单独测量，报告源事件产生到展示的时延；不把轮询等待隐藏在指标外 |
| AI 等待反馈 | 请求发出后 300ms 内出现等待状态与取消入口；外部服务完成时间不做固定保证 |
| 启动 | 在约定测试机上，常规冷启动至基础交互可用目标 ≤ 5 秒 |
| 动画 | 正常屏幕动画目标 15～30fps，可按资源降级；静态时不无意义地持续高频重绘 |
| 待机 CPU | 约定测试机连续采样，目标均值 ≤ 2%，明确计算口径 |
| 待机内存 | 桌面客户端与桥接服务合计目标 ≤ 300MB，超出需说明原因并调整实现 |
| 稳定性 | 桌面 24 小时混合场景测试无崩溃，无持续增长的资源泄漏 |
| 数据可靠性 | 正常退出、异常退出与重启测试中，不出现已经显示保存成功却丢失的待办 |
| 安装与分发 | 本地预览与正式安装包分开；公开分发前完成签名／安全更新方案评审 |
| 兼容性 | 首发 Windows 11；其他系统不在首版保证范围 |
| 中文显示 | 覆盖内置文案、常用任务文字和缺字回退，不能在核心状态中显示不可读方框 |
| 实体性能 | 固件内存、显示刷新、网络与音频并发预算必须实测，PC 性能不作替代证据 |

不得为了性能指标关闭权限校验、隐私提示或错误反馈。

- 20 个确定的设备页面／表现采样点。

### 15.3 未实现能力的处理

- 未接入真实 AI：真实 AI 验收标为未完成，不能用演示替代。
- 未接入设计／办公插件：只能声明 L0 覆盖，不声明深度集成完成。

## 17. 成功指标与试用验证

### 17.1 首轮验证重点

首轮不以“聊天次数越多越好”为目标，而验证：

1. 用户是否愿意在真实工作日保持它运行。
2. 用户是否利用它获知任务结果或完成计时／记录。
3. 提醒是否有帮助，是否造成打断。
4. 用户能否准确区分模拟、真实事件与 AI 推测。
5. 用户是否认为购买实体版本有额外价值。

### 17.2 建议记录的指标

- 首次启动到完成第一个计时／待办的时间。
- 各场景有效使用次数，默认只在本地观察或征得同意后收集。
- 真实任务结果的正确展示率、漏报和重复提醒数。
- 本地事件到显示的 p50／p95 时延。
- 用户主动关闭声音、隐藏或退出的原因。
- 实际 AI 成本与取消率，在获得可靠数据后展示。
- 问题反馈和用户是否感到被打扰。

商业留存、付费转化等目标在试用获得基线后制定，不将没有数据的百分比写成市场结论。

## 18. 风险、依赖与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 裸开发板没有屏幕／音频 | 外观方案与实际无法对应 | 严格区分扩展件，先建立参考装配 |
| 不同板卡修订与兼容板差异 | 孔位、USB、指示灯或引脚不一致 | 锁定版本与来源，不泛称“所有 S3 板通用” |
| PC 原型看起来流畅，但设备资源不足 | 固件移植失败或动画卡顿 | 尽早验证共用 UI，控制字体／资源／缓冲预算 |
| 中文字体和动态图像占用高 | 内存与 Flash 压力 | 固定字体与资源策略，测试缺字回退，按实际容量裁剪 |
| 软件缺少公开状态接口 | 无法实现承诺的实时集成 | 先做能力调研，保留 L0／L1 路径 |
| AI 幻觉或错误动作 | 虚假进度、误操作 | 业务事实由事件层决定，有限动作校验 |
| 桌宠过于打扰 | 用户关闭或卸载 | 默认安静，勿扰、合并通知、减少动画 |
| 桌面与实体通知重复 | 打断用户 | 共享事件去重，设置主要通知终端 |
| API／网络不可用 | 核心体验停摆 | 本地计时、待办与状态独立运行 |
| 内容授权范围不清 | 隐私泄露 | 分享预览、最小范围、独立权限、可撤销 |
| 回放数据污染真实数据 | 待办／记录错乱 | 独立 simulation 命名空间与存储分区 |
| 新手接线或供电错误 | 损坏硬件、调试困难 | 首版 USB 与低压模块，提供审核后的接线文档；不直接用 GPIO 驱动扬声器或大负载 |
| 过早量产 | 返工与成本扩大 | 桌面价值验证→固件验证→实体样机→产品化逐级推进 |

## 附录 A：首版交互样例

### A1 编码

用户启动：`单元测试` → 伙伴显示“正在测试” → 收到明确失败结果 → 伙伴显示“有 2 项需要检查” → 用户打开详情 → 主动选择相关日志 → AI 提供解释。

没有测试数量时，文案应为“测试失败，查看结果”，不能自行补数字。

### A2 设计

用户创建“首页视觉”会话 → 开始 25 分钟专注 → 到时仅提醒休息 → 用户选择“继续”或“结束” → 主动提交导出图与设计目标 → AI 给出建议。

计时结束不自动代表设计完成。

### A3 文档

用户输入“明天下午改方案” → 生成待办草稿 → 确认具体时间与标题 → 本地保存 → 回报“已记录”。

未保存成功时，不播放代表成功的庆祝动画。

### A4 娱乐

用户切换休息模式 → 伙伴显示轻松表情 → 按确认键开始反应小游戏 → 任意时刻可以返回 → 正在后台运行的任务若结束，按提醒策略呈现结果。

### A5 断线

真实任务运行中 → 来源适配器失联 → 显示“状态待确认” → 适配器重连并同步终态 → 显示实际结果，最多提醒一次。
