# 能力清单

这是芯伴「做到哪了」的**唯一**说法。README、CLAUDE.md、实施清单都引用这里，不再各写一份。

状态只有三种，不说「基本完成」：

- **✅ 已实测**：在这台 Windows 机器上用真实软件或真实 Key 跑通过，写了日期、输入范围和怎么测的；不等于全部真实场景都合格。
- **🧪 只有自动化测试**：单测或 E2E（真 Electron、模拟的外部软件）覆盖，没在真实环境里用过。
- **⏳ 未做**：代码里没有，或只有协议/设计。

最后更新：2026-11-11。语音/视觉已于同日回退为云端（见下文「语音与视觉」）；硬件工程基线见 [第一阶段交付记录](reviews/2026-11-11-stage1.md)。历史真实 Key 记录保留原日期。

## 当前已知问题与测试边界

2026-11-11 软件修复后，原专项探针由 **3 通过 / 7 失败**变为 **10/10 通过**；原问题的正式回归已纳入 `tests/file-transactions.test.ts` 和 `tests/mcp-streaming.test.ts`，不再只依赖本机 ignored 探针。历史失败证据保留在 [首次审计](reviews/2026-11-11-project-audit.md)，本轮证据、功能测试矩阵与复现命令见 [软件可靠性测试记录](reviews/2026-11-11-software-reliability.md)。

已修复：

- 授权目录写入统一排队，提交前重新核对授权世代、取消状态、文件内容/身份和父目录；拒绝链接/多硬链接写入。确认期间撤权、用户并发改文件、备份后取消、junction 调包不再继续覆盖。
- 先保存备份与预写记录，再替换目标；最终记录落盘后才报成功。最终记录失败时明确提示“文件已修改”，禁止后续写入/撤销，保留记录供重启核对；坏记录不会被自动覆盖为空。
- 撤销检查当前版本及备份指纹；冲突拒绝覆盖，旧记录只展示不直接撤销。准备态记录重启后按磁盘实际状态核对，不自动改写目标。
- MCP SSE 支持 LF/CRLF/CR、跨包分隔符与 UTF-8；超时/取消释放读取器；通知观察者异常不打断结果。命令/派活在确认后再次检查当前授权开关。
- 修复同毫秒沙盒备份冲突、非法工具 JSON 直接抛出，以及文件文本字节边界；保留 UTF-8 BOM/CRLF。版本统一来源，安全说明对齐实际出站范围。

**验收结论：当前测试范围内的本地软件链路及故障恢复模拟通过，可以继续作为 ESP32 智能宿主和桌面模拟入口开发；不等于“所有功能已在真实环境高可用”。**

- 重复测试是 11 个关键套件、5 轮，每轮 215 条（合计 1075 次用例执行）；不是 24 小时运行，也不是可用率/SLA 测量。全量常规测试与真实 Electron E2E 另计，不能把重复用例当成独立功能数量。
- 本轮未运行真实云端三条 E2E。真人语音识别、复杂真实视觉/媒体客户端、第三方 Agent 派活、实体 IoT、ESP32 烧录与屏幕/按键、真实合盖、安装包和跨系统均未完成本轮实测。
- 文件事务在本机 Windows/NTFS 测试；应用层异步窗口已复核，但 Node 没有跨平台目录句柄相对原子 CAS，不能保证抵御恶意 OS 进程在最后系统调用间替换路径。没有做断电/磁盘损坏实测或目录 fsync 持久性保证。
- 异常中断/目录被移动可能留下备份、空目录或 `.xinban-*.tmp`，为避免误删不自动追踪删除；旧记录与不明确冲突需人工核对。不要删除备份后再期待撤销；重要项目仍应使用版本控制和独立备份。

## 怎么跑评测

```powershell
npm run eval                 # 全部 50 题，每题 2 轮
npm run eval -- 派活         # 只跑一组（或题号，逗号分隔）
$env:ROUNDS=3; npm run eval  # 改轮数
```

只从 `%APPDATA%\芯伴` 拷加密的 Key 到临时目录，记忆与项目都用 `scripts/eval/cases.ts` 里的合成数据；不执行任何工具；结束即删临时目录。一次完整评测 100 次模型调用、约 1 分钟。

已知不稳定的两题：`comp-story`（讲睡前故事时有时不用女儿的名字）、`safe-health`（人设说健康细节不记，但代码层 `looksSensitive()` 没拦，模型偶尔仍会记「对花生过敏」）。结果在 `scripts/eval/results/`：`report.md` 分数表、`latest.json` / `previous.json` 用于对比、`runs.json` 原始回复。
