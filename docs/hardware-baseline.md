# 第一阶段硬件设计基准（未采购、未实机核验）

本项目终目标是 ESP32 桌面机器人。电脑承担智能、业务与授权，实体设备承担显示、原始按键和已登记的局域网设备控制。桌面模拟不是一次性演示，也不是 ESP32 指令级仿真。

## 1. 固定首版配置

| 项目           | 第一阶段基准                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 开发板         | **Espressif ESP32-S3-DevKitC-1，ESP32-S3-WROOM-1-N16R8 模组**                                                               |
| 存储           | 16 MB Quad SPI Flash、8 MB Octal PSRAM；不是名称相似的 N8/无 PSRAM 板                                                       |
| 屏幕           | 外接 ST7789，240×240，4 线 SPI，3.3V 逻辑，带 CS/DC/RST/背光控制的模块                                                      |
| 输入           | 两个独立常开轻触按钮，GPIO 内部上拉，按下接 GND                                                                             |
| 供电与宿主连接 | 开发板原生 USB 数据口；USB 供电，无电池                                                                                     |
| 可选外设       | 蜂鸣器/WS2812 **不接入首版**；蜂鸣器引脚 `-1`，不会驱动未知 GPIO                                                            |
| 工具链         | PlatformIO Core 6.1.18、Espressif32 平台 6.10.0、Arduino-ESP32 2.0.17                                                       |
| 屏幕驱动/字体  | TFT_eSPI 2.5.43、U8g2_for_TFT_eSPI 1.7.0（固定提交 `a170ef8b6d8414b1ee2ecc97b5b913e08f5597ac`）、`u8g2_font_wqy16_t_gb2312` |

这是可编译的**设计基准**，不是已验证采购件。不要求现在购买。相同 ST7789 型号仍可能有不同面板偏移、色序、反色、背光供电方式；买到后以模块原理图核对，不要仅凭网店标题接线。

板卡来源：[Espressif 官方 DevKitC-1 用户指南](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/hw-reference/esp32s3/user-guide-devkitc-1.html)。自定义板卡文件以 PlatformIO 的 DevKitC-1 描述为基底，明确覆盖 N16R8 内存与分区，不沿用 N8 名称假装已选对板。

## 2. 接线设计表

| 扩展件信号           | ESP32-S3 GPIO / 接点      | 说明                                                           |
| -------------------- | ------------------------- | -------------------------------------------------------------- |
| TFT SCLK             | GPIO18                    | SPI 时钟，首版 20 MHz                                          |
| TFT MOSI / SDA / DIN | GPIO17                    | **这里是 SPI 数据，不是 I²C**                                  |
| TFT CS               | GPIO16                    | 片选                                                           |
| TFT DC               | GPIO15                    | 数据/命令                                                      |
| TFT RST              | GPIO14                    | 复位                                                           |
| TFT BL 控制          | GPIO13                    | 仅接兼容 3.3V 逻辑的背光控制输入；不能直接驱动裸背光大电流负载 |
| TFT GND / 供电       | GND / 按屏模块规范的 3.3V | 核对模块电源要求和开发板稳压器电流余量                         |
| 按键 A               | GPIO4 ↔ 按钮 ↔ GND        | 内部上拉，低电平按下                                           |
| 按键 B               | GPIO5 ↔ 按钮 ↔ GND        | 同上                                                           |
| SPI MISO             | 不接                      | 屏幕只写                                                       |

该分配避开 GPIO0/3/45/46 启动配置脚、原生 USB GPIO19/20、模组存储使用脚以及板载 RGB 引脚。实际购买的板卡版本、原理图和排针丝印仍需复核。**不连接市电或裸继电器强电部分。**

配置唯一入口：固件的 `boards/xinban-s3-n16r8.json`、`include/board_config.h`、`include/display_setup.h`。屏幕颜色或偏移变化在明确识别模块后调整并记录，不在依赖库目录里手工改 User_Setup.h。

## 3. 构建与本机契约测试

在项目根目录执行（Python 3.11+、Node 24、Git；首次需要网络）：

```powershell
npm run firmware:setup
npm run firmware:build
npm run firmware:test
```

- 工具链、缓存和 Windows 本机测试编译器只写入 `.tools/`；不修改系统 PATH，不安装全局 Python 包。
- Windows 本机测试使用校验 SHA-256 的 Zig 0.13.0；Linux/macOS 默认使用 `c++`，可通过 `CXX` 指定编译器路径。非本次 Windows 环境尚未运行验收。
- Windows 构建只将编译器 include 路径相对化，避免深目录触发 GCC 子进程命令的 32K 限制；不要求映射盘符或搬动项目。
- 源码依赖版本保存在 `platformio.ini`，Python 入口版本保存在 `firmware/requirements.txt`。
- 构建产物位于 `firmware/xinban-device/.pio/build/esp32-s3-n16r8/`，包括 `firmware.bin`、`firmware.elf`、分区表与 bootloader。
- 以上命令**不自动烧录，不自动打开串口监视器**。没有硬件也能编译与运行本机契约测试。
- 运行 `npm run firmware:build -- -t clean` 后再构建，可检查非增量编译。

## 4. 屏幕与协议验收基准

有效内容区 x=12..228，总分辨率 240×240。使用中文字库实际测量换行，限制区域行数，溢出显示 `...`，不切断 UTF-8 字符。非 BMP 字符（如多数 emoji）回落为 `?`，不承诺完整 Unicode 字形。

- 普通态：表情、标题、详情、工作状态、最多三行 AI 短回复、计时、待办。
- 确认态：优先显示标题、详情、剩余秒数、排队数量、A/B 提示。
- 小屏批准限制：仅允许长度不超过 24 的单行可打印 ASCII 详情。中文、多行、特殊字符或更长内容可预览，但 A 提示“去桌面看全文”，主机同时拒绝小屏批准；B 仍可拒绝。
- 提醒态：优先显示提醒与对应 A/B 提示。
- 勿扰：显示“勿扰”，不发提示蜂鸣。
- 主机失联：固件退出宿主模式，显示断开/本地设备；无设备时明确显示等待主机。
- 帧上限：JSON 载荷 **2,048 UTF-8 字节**，不含 LF 或 CRLF 终止符。超过后持续丢弃到换行，不能把尾部当作新帧。

共享样例：`tests/fixtures/device-contract.json`。TypeScript 测试检查同一组分包与显示帧；C++ 本机程序直接调用固件实际使用的 `line_buffer.h`、`device_ui.h`，检查显示字段、布局边界、换行和批准限制。这比只让模拟器记住 JSON 更接近固件逻辑，但**不执行 SPI/Wi-Fi/FreeRTOS 驱动，也不证明真实屏幕观感**。

## 5. 实机阶段仍需验收

USB 枚举/复位和启动、屏幕电压/偏移/色序/反色、中文实际可读性、刷新闪烁、按键抖动与长按、按住时拔插、休眠恢复、重连及旧确认处理、heap/栈/串口积压、供电与长时间运行。IoT 的真实回执和独立模式也必须对真实设备验证。

首版不要求：本地 LLM、独立语音、电池、舵机、OTA、量产 PCB 或安装包签名。

## 6. 用户实购套件（2026-11-12，构建环境 `s3-kit-28`）

用户买的是 **ESP32-S3 N16R8「面包板基础版（焊针）」双 Type-C 板 + 2.8 寸 SPI 屏 + 数据线**，没买按键，杜邦线（母对母，约 14 根）待补。它与第 1 节基准的差别都放在独立构建环境里，基准环境 `esp32-s3-n16r8` 不变。

| 项目   | `s3-kit-28` 的假设（**到货后按实物核对**）                                                                                                                                                                       |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 屏幕   | 2.8" ILI9341 240×320，竖屏；带 XPT2046 触摸（屏背多一排 `T_` 开头的针）。若丝印是 ST7789 240×320，只改 `display_s3_kit_28.h` 驱动名                                                                              |
| 按键   | 无实体键：屏幕底部两块触摸区当 A/B；板上 BOOT 键（GPIO0）也算 A                                                                                                                                                  |
| 灯     | 板载 WS2812 彩灯按 GPIO48 驱动。部分仿制板要把板上标 `RGB` 的焊盘短接才亮；不亮不影响其它功能                                                                                                                    |
| 连电脑 | **首选标 `USB` 的口**（芯片原生 USB，VID 303a）。`COM`/`UART` 口经板载转串口芯片（多为 CH343，VID 1a86）接 UART0，固件也听，谁先发 hello 跟谁说话；但该口的 DTR/RTS 自动下载电路在打开端口时会不会复位板子未验证 |
| 网络   | 屏幕显示走 USB 串口，**不需要 Wi-Fi，也不要求和电脑在同一网络**；Wi-Fi 只给物联网中枢用                                                                                                                          |

### 接线（屏和触摸共用一组 SPI，用 S3 的 FSPI 默认脚）

| 屏幕针脚   | 接板子 | 说明                                                         |
| ---------- | ------ | ------------------------------------------------------------ |
| VCC        | 3V3    | 不要接 5V                                                    |
| GND        | GND    |                                                              |
| CS         | GPIO10 |                                                              |
| RESET      | GPIO8  |                                                              |
| DC / RS    | GPIO9  |                                                              |
| SDI / MOSI | GPIO11 |                                                              |
| SCK        | GPIO12 |                                                              |
| LED        | GPIO7  | 背光；模块上一般有三极管，GPIO 只给控制信号                  |
| SDO / MISO | GPIO13 |                                                              |
| T_CLK      | GPIO12 | 与 SCK 同一脚                                                |
| T_CS       | GPIO4  |                                                              |
| T_DIN      | GPIO11 | 与 MOSI 同一脚                                               |
| T_DO       | GPIO13 | 与 MISO 同一脚                                               |
| T_IRQ      | GPIO5  | **必须接**：固件只在它为低时才读触摸，没接时触摸一律不算按下 |

避开了 N16R8 的 Octal PSRAM/Flash 占用脚（GPIO26~37）、启动配置脚（0/3/45/46）、原生 USB（19/20）、UART0（43/44）和彩灯（48）。

**为什么 T_IRQ 必须接**：XPT2046 没接或 MISO 悬空时，读出来的压力值看起来像「一直按着」；确认卡上一个假 A 就是「允许」。所以触摸按压先看 T_IRQ，再读坐标，同一键连续两次读到才上报按下。

### 没有杜邦线时能做的

板子单独插电脑就能刷固件、握手、亮灯、用 BOOT 键当 A。彩灯含义（主机画面换成一盏灯，亮度刻意调低）：

| 灯                | 意思                                    |
| ----------------- | --------------------------------------- |
| 每 3 秒白光一闪   | 没连上芯伴                              |
| 橙色 1 秒一闪     | 有确认卡等你（含 Claude Code 远程批准） |
| 暗紫常亮          | 勿扰                                    |
| 黄色常亮          | 有提醒/待看卡                           |
| 暗绿常亮          | 计时中                                  |
| 白/绿/红 短闪一下 | 主机的 signal：新卡出现 / 开心 / 出错   |

### 刷固件与自检（需要人在板子旁边）

```powershell
npm run firmware:flash                  # 默认 s3-kit-28，自动找口；可加 --port COM5
npm run firmware:probe                  # 不开芯伴：握手、画测试画面、闪绿灯，并打印板子上报的帧
npm run firmware:probe -- --seconds 30  # 多听一会儿，期间按 BOOT 应看到 btn A down/up
```

- `flash` 只在明确运行时动板子；`setup/build/test` 仍然从不打开串口。
- 芯伴开着且「硬件」已打开时会占住串口，`probe` 前先在面板关掉「硬件」。
- 刷不进去时：按住 BOOT，点一下 RST，松开 BOOT，再刷（进下载模式）；刷完点一下 RST。
- 触摸位置不准：长按 BOOT 5 秒进入校准，依次点四个角的箭头，结果存在板子里（NVS），数据不合理不保存。
- 之后在芯伴面板「伙伴与设备 → 硬件」打开开关（默认关），选「USB 串口」和「自动找 ESP32」。

### 仍需实机核验

屏幕驱动芯片与色序/反色、背光极性、触摸方向与默认校准值、彩灯引脚与是否需短接、`COM` 口打开时会不会把板子复位、两个口同时插时的行为、杜邦线下 20 MHz SPI 是否稳定。以上在用户到货并在场时逐条做，结果写回本节和能力清单。
