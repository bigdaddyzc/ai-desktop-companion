## 0. 结论

芯伴的**说话和记忆问答已经不错**：真实模型考题里，闲聊、记忆、安全拒绝、待办/计时/搜索等工具选择几乎全对，语气也对。

问题集中在**你最常用的那条线——派活和盯 AI**，而且是结构性的：

4. **出了错查不到**：没有运行日志，没有派活历史。唯一一次派活失败，原因没留下来。
5. **大量功能从没在真机上跑过**：替你确认、官方钩子、音乐、讲故事、云端语音、视觉、确认流整链。文档和代码也有 12 处对不上。

## 3. 关键发现（按严重程度）

### F1 「替你确认」的「永远找你」清单可绕过（安全，最高）

前提：你在同一项目里亲手批过一次很常见的操作（`git diff`、`echo`、改文件）。之后下面这些都会被当成同类自动批准。前 4 条本轮已用钩子脚本本体复现：

| 写法                                                        | 钩子判成               | 实际效果                                       |
| ----------------------------------------------------------- | ---------------------- | ---------------------------------------------- |
| `diff <(rm -rf /c/Users/me/Documents) a.txt`                | `diff`，无风险         | 删文件                                         |
| `GIT_EXTERNAL_DIFF="rm -rf ~ #" git diff`                   | `git diff`，无风险     | 删文件                                         |
| `Write-Output (Remove-Item C:\Users\me\Documents -Recurse)` | `write-output`，无风险 | 删文件                                         |
| 改 `项目/.claude/settings.local.json`                       | 「改文件」，无风险     | 可写入「全部放行」，整张清单当场失效           |
| 你**拒绝**过的请求，配上同会话一次未弹窗的同类操作          | 被「学会」为批准       | 你拒绝的事以后自动批（读代码确认，未实机复现） |

另有中等问题：`${HOME}`、`%USERPROFILE%` 这类路径不算「改项目外」；通配符能绕开密钥检测；`node --eval=...` 被当成普通 `node`；`curl -H @文件` 不算上传。开关关着时也在「学」，一打开就全部生效。

**当前实际暴露**：很低。已学会的批准是空的，Claude Code 钩子又刚被冲掉。但 WorkBuddy / CodeBuddy 的钩子还在，开关是开着的。

### F2 派活派不到你的项目里（最常用的功能，结构性缺口）

- `src/desktop/delegate.ts` 里外包出去的 Agent 一律以 `userData/workspace` 为工作目录；`delegate_task` 只有 `task` 和 `target` 两个参数，说不了「在 D:\xxx 项目里干」。
- 模型也看不到你有哪些项目，只好先去翻自己的沙盒目录。考题结果（多步模拟，只读工具给中性桩结果）：

| 说法                                      | 派出去 | 其余去向                             |
| ----------------------------------------- | ------ | ------------------------------------ |
| 「把登录页那个 bug 交给 Claude 修一下」   | 0/3    | 翻目录后反问你项目在哪               |
| 「把 D:\…\demo 里的登录 bug 交给 Claude」 | 0/3    | 2 次自己去跑系统命令，1 次一直翻文件 |
| 「让 Claude 给 demo 项目补个单元测试」    | 0/3    | 反问路径 / 自己跑命令                |
| 「让 Claude 读 research/… 重写分析」      | 1/3    | 反问或想自己写                       |
| 「让 WorkBuddy 查 aier 项目…」            | 3/3    | ——                                   |

你明说「交给 Claude」时，**12 次只派出 1 次**，还有 2 次它绕过派活自己跑命令。

附带问题：没有派活历史（上次失败原因没留下）；取消落在启动前的瞬间会失效，子进程跑到超时、对话卡死最长 120 分钟（M7）；自定义 .cmd 目标里 `%`、换行会被 cmd 改写（M5，已实测）。

### F3 钩子被 cc-switch 冲掉，芯伴无感知

- cc-switch 日志 `2026-11-10 10:28:55`：「检测到上次异常退出…正在恢复 Live 配置」「claude Live 配置已从备份恢复」「codex Live 配置已从备份恢复」。
- 同一秒 `~/.claude/settings.json` 被改写，只剩 `enabledPlugins`、`env`、`includeCoAuthoredBy`，芯伴装的钩子没了。芯伴自 11-09 起装过 3 次，每次都被冲掉。Codex 的 `notify` 同样。
- 之后 Claude Code 事件归零；你在面板上看不到任何提示。
- 注意到 `enabledPlugins` 在改写后保留了——把钩子做成 Claude Code 插件可能不会被冲掉，需要验证。

### F4 出了错查不到

- `%APPDATA%\芯伴` 和仓库里没有任何日志文件。
- 派活只存配置，不存运行记录。唯一一次失败（11-09）只留下一句提醒文案。
- 钩子事件文件只追加不轮转；其中约 3 成是测试产生的（`xinban-approve-test`），测试数据和你的真实数据混在一起。

## 4. 原则

1. **冻结新功能**，直到第 6 节的验收全部通过。
2. **每项都有可检验的验收**，而且至少一项是真机或真实服务。只有单测的不算完成。
3. **安全问题先于一切**：没修好之前，相关功能默认关闭。
4. **考题集是基础设施**：改提示词、换模型、改工具描述，都要先跑一遍。
5. **文档只留一份「能力清单」**，标明已实测/未实测，其余文档引用它。

### 第二阶段：稳住（P1）

#### P1-1 可观测性

- 滚动日志 `logs/app-YYYYMMDD.log`，保留 7 天：只记事件与错误（哪个模块、什么失败、错误码），**不记对话内容、不记 Key**。
- 钩子事件文件按天轮转，只留 7 天。
- 测试与实测一律使用隔离目录，不再往真实数据里写；清掉已有的测试事件。
- 面板「体检」卡：AI 配置、各钩子、各派活目标、语音/视觉 Key 的在线状态，一眼看到哪里断了。

#### P1-2 对话链路可靠性

逐一修掉 F5 表里的 7 项，每项带回归测试。重点是 M6：改成「空闲超时」，只要还在出字就不掐；真正超时时报「单步超时」而不是「连接中断」。

## 7. 风险

- **钩子装法可能没有一劳永逸的解**：cc-switch 的行为不归我们管。最差情况是「丢了马上知道、一键重装」，这一点 P0-4 保证。
- **派活到你的项目意味着外部 Agent 会改你的代码**：只允许你登记的目录；派活前仍然逐次确认；确认卡上写明项目名。
- **收紧「替你确认」会让它替你批得更少**：这是有意的取舍，宁可多弹窗。
- **考题会花一点 DeepSeek 额度**：本次 74 次调用，输入约 5k token/次。
