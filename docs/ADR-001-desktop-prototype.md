# ADR-001：Windows 桌面体验原型

- 状态：本次实现采用；可在固件一致性验证阶段调整。
- 日期：2026-11-07。

## 决策

采用 Electron + React + TypeScript + Vite。理由是当前机器已有 Node.js，可直接构建透明窗口、托盘和受控本地持久化，而不先引入 Rust／嵌入式工具链。

领域状态机不依赖 UI，协议输入以 Zod schema 校验。Electron 主进程拥有状态；两个窗口只订阅快照并发送白名单动作。preload 仅暴露固定方法，不暴露 ipcRenderer、文件路径或 shell。

本地真实数据与模拟数据分区。任务模拟只存在内存；真正的个人待办、会话、设置及计时存入用户数据目录。采用串行更新、临时文件＋rename、写入后发布。损坏／不兼容文件保留原件并进入只读安全状态，而非静默覆盖。

## 信任边界

- 渲染器不具备 Node 权限；IPC 校验发送窗口和顶层文档地址，再校验动作格式。
- 禁用未经请求的权限、外部导航、新窗口、webview。
- 不开放生产网络端口。开发服务器仅绑定 127.0.0.1。
- 没有 AI 凭据字段、云端请求、遥测和应用监控。当前助手为有标识的本地预设演示，不接受自然语言命令。

## 计时

进程内使用注入式逻辑时钟，主进程以单调时钟增量推进。正常运行不受系统时钟调整影响。重启后的未完成计时进入“等待恢复”，用户决定继续／结束，禁止自动补发一串提醒。此阶段系统休眠差异仍需单独测试。

## 不代表已经实现

React 设备屏幕目前是体验原型，不是 LVGL 共用渲染，不承诺像素级实体一致性。ESP32 驱动、精确板卡尺寸、GPIO、固件仿真、音频、自动工作适配器均留待后续。不会把重新设计的概念板卡当作精确复刻。

## 目录

- `src/core/`：schema、状态转换、展示选择器。
- `src/desktop/`：主进程、preload、存储与状态服务。
- `src/renderer/`：伙伴窗口和控制面板。
- `tests/`：领域与存储测试。
- `e2e/`：真实 Electron 窗口测试。
- `scripts/`：构建、启动工具。

## 后续决策门槛

在精确外观和固件开发前核验板卡版本、模块和外设；在选择 LVGL 集成路径前完成资源／渲染验证；工作事件包装器与插件接入需要独立协议和权限设计。本次不提前建立没有消费者的网络服务。
