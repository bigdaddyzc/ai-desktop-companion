## 本轮增量：F-08 流式输出（2026-11-07 第五轮）

用户要求用其提供的 Key 完成实施清单上的开发工作。第五轮把 AI 对话从「整段等待」改为流式，并补上第四轮遗留的真实往返验证。

实现：

- `src/core/ai.ts`：新增增量 SSE 解码器（缓冲到空行才产出事件，兼容 CRLF、多行 data、注释行、末尾无空行）、单块解析、流式中断文案。请求体支持 `stream: true` 与 `stream_options.include_usage`。
- `src/desktop/ai.ts`：新增 `chatStream`。逐块解析并回调增量，`[DONE]` 后收尾；HTTP 错误在读流前就返回；取消／超时／连接中断丢弃半截内容并明确说明，不把未完成的回复当成完整答案。
- `main.ts` / `preload.ts` / `schema.ts`：新增 `aiChatStream` 与只读订阅 `onAiDelta`。增量按约 50ms 合并后只推回发起请求的控制面板，结束前一定 flush，不广播给伙伴窗口。
- `AiPanel.tsx`：收到增量即显示「正在回复」气泡，结束后替换为正式气泡；迟到分片被忽略，不会残留半截气泡。
- 推理型模型的 `reasoning_content` **不上屏**：它是内部推理，不是给用户的回答。若输出额度全被推理吃光、正文为空，提示语改为可操作的说明，而不是笼统的「没有返回内容」。

**真实流量暴露的两个缺陷**（都是「对服务端字段过敏」）：

1. 首版把 `delta.content` 用 Zod 宽松对象解析，但真实分块每块都带 `"usage": null`，而 schema 只允许 `usage` 缺失。结果每一块都被判为「不认识」，整段回复被吞掉，界面报「模型没有返回任何内容」。已改为同时接受 `null` 与缺失，并保留真实分块结构的回归用例。
2. 服务端在同一 `delta` 里混发 `role`、`reasoning_content`、`finish_reason: null`。已改为结构不认识就跳过该块，而不是中断整段回复；只有 JSON 无法解析或服务端在流中回 `error` 对象才报错。

另修复一个并发竞态：`busy` 原本在读取凭据之后才置位，异步读取期间第二个请求能溜进来。现在非流式与流式都在鉴权读取前占位，并由 `finally` 复位。

真实验证（用户提供的 Key，只经环境变量传入，不写入任何项目文件）：

- 直连 `POST https://api.deepseek.com/v1/chat/completions`（`stream: false`）：HTTP 200，回复「你好」，42 tokens。
- 直连流式：HTTP 200，12 个分块，正文「桌面伙伴」，`usage` 74，`delta` 同时含 `reasoning_content`。
- 应用链路（UI → IPC → 加密凭据 → 主进程 → DeepSeek → 增量上屏）：E2E 断言增量拼接结果与最终正文完全一致，界面显示「1 次请求 · 82 tokens」。

## 本轮增量：F-05 休眠与系统时间跳变（2026-11-07 第六轮）

计时时钟是「启动时的墙钟 + 单调时钟增量」。系统休眠时单调时钟停走，因此睡眠期间计时不会推进——此前这是静默的：用户合盖一夜，回来发现计时还剩很多，界面不作任何说明。

现在：

- `StateService.tick` 每秒比较墙钟增量与单调时钟增量，偏离 ≥ 5 秒即认定发生过休眠或用户改时间（`src/desktop/service.ts`）。
- 命中的是运行中的计时，则转到 `recovery` 待确认状态，`recoveryReason` 记为 `clock-jump`，保留当前剩余量；**不用墙钟静默补算**——睡眠期间该不该继续计时只有用户知道。
- `timer.clock-jump` 是主进程内部动作，不在 IPC 的 `actionSchema` 里，renderer 无法伪造。
- 面板文案区分两种待确认：「应用已重启」与「检测到休眠或时间跳变」；`timer.start`／`resume` 会清除原因。
- 旧版数据里的 `recovery` 计时没有原因字段，读取时按「重启」处理，不因此拒绝加载（不做强制 refine）。

验证：核心状态机与服务层各有单测（触发、待确认期间不走表、暂停／无计时时忽略、正常 tick 与 800ms 小抖动不触发）。**没有做真实合盖休眠实测**，也没有在挂起／恢复的系统事件上验证，只覆盖了时钟偏离这一可观测信号。

## 本轮增量：对话搬到桌宠小屏（2026-11-07 第七轮）

用户在实机上反馈两件事：问了天气，伙伴回答「我这边没法联网查」；而且**回复没有出现在屏幕上**。

第二个是真实缺陷，不是误解：AI 回复只渲染在控制面板的 `ai-log` 里，桌宠窗口的代码里根本没有 AI 展示位（`AiPanel.tsx` 旧注释还写着「桌宠窗口不提供输入入口」）。对话状态原本保存在面板窗口的 React state 里，两个 BrowserWindow 各自独立，天然同步不了。

改法是把对话的所有权移到主进程：

- `src/core/ai-session.ts`：纯状态。`beginRequest` / `appendDelta` / `settle` / `fail` 四个转移函数，加 `lastExchange` 与 `historyFor`。状态只在内存，不落盘、不进导出。
- `src/desktop/ai-session.ts`：`AiSessionService` 持有唯一会话，`send` 内合并 50ms 增量后广播；一次只允许一个请求。
- `main.ts`：`companion:ai-session` / `ai-send` 对两个应用窗口开放（仍逐次 `verify` 来源窗口与顶层 frame），`ai-configure` / `ai-clear` 仍限控制面板。
- 桌宠：`PetWindow` + `Device` 增加对话视图。顶栏「✎ 说话」打开输入，屏幕切为对话层显示问答并自动滚到底；新一轮提问开始时自动切过去，用户手动收起后不会被增量更新反复弹开。
- 桥接层收敛：删掉 `aiChat` / `aiChatStream` / `onAiDelta` 三个旧入口，统一为 `aiSession` / `aiSend` / `onAiSession`，避免两套状态并存。

开发中被单测抓到一个真 bug：`lastExchange` 最初把「最后一次提问」直接配「最后一次回答」，请求失败时会显示成「第二问 → 第一答」。已改为回溯最近一条**已完成**的回答并配它前面的提问。

联网问题不是缺陷：`/chat/completions` 是纯文本补全，没有检索能力，我们也没给模型工具调用。此前系统提示词没说明这点，模型只能说「没法联网」；现在提示词明确「没有实时信息，查到就说查不到、建议去哪查，不要猜数值」，面板与 README 也写清了这一边界。要真能查天气，需要另接搜索服务或工具调用，属于独立功能。

验证：363 单测（新增 21 项覆盖会话转移、失败丢弃半截、并发拒绝、历史构造与截断）；12 项 Electron E2E 全通过，含真实 Key 往返——面板提问后断言桌宠小屏出现同一段回复。**做过一次失败注入**：临时去掉桌宠的自动切换，真实往返用例在「桌宠对话可见」处失败，恢复后重新通过，确认该断言不是恒真。

## 本轮增量：Responses API 与工具循环（2026-11-07 第八轮）

用户提出三件事：需要搜索能力、能不能用 Responses API、要它「像 person agent 一样干活」。

先查官方文档再动手，避免了两个凭印象会写错的地方：

- DeepSeek **已支持** Responses API，base_url 是 `https://api.deepseek.com`（不带 `/v1`），端点 `/responses`。用户面板里填的是 `.../v1`，所以端点按 origin 推导，不能拼成 `/v1/responses`。
- **已提供官方 Search / Fetch**：`POST /v1/tools/search`、`POST /v1/tools/fetch`，5 元／千次成功请求，失败与无结果不计费，Search 100 QPS、Fetch 25 QPS。不需要另接 Bing／Serper。
- `web_search` 作为**服务端内置工具只有 `deepseek-v4-pro` 支持**，`deepseek-flash` 会静默忽略。因此走「flash + 自建 function 工具循环」，工具由我们执行，过程可见、来源可留。

实现分层：

- `src/core/responses.ts`：端点推导、请求体、语义化 SSE 事件解析、`output` 条目读取、用量映射。无状态：每步都重传完整 `input`（含 `function_call_output`）。
- `src/core/agent.ts`：11 个工具的 JSON Schema、调用摘要、搜索结果格式化（按 `rerank_score` 排序）、`wrapUntrusted` 包裹、来源去重、循环签名。
- `src/desktop/tools.ts`：执行器。文件路径必须解析到工作目录内；命令 `spawn` 且 `shell: false`、白名单 `node`／`git`／`python`／`python3`、20 秒超时、8 KB 输出上限；写入前备份 `.bak`；`package.json`／`node_modules`／`.git`／可执行文件禁止写入。
- `src/desktop/ai.ts`：`runAgent` 多步循环（8 步、14 次调用、150 秒），每步把 `output` 追加进 `input` 并回填工具结果；同一批调用原样重复时停止；步数用尽后不带工具再要一次结论。
- 界面：面板新增「本次工具」与「来源」，来源去重限 6 条、点击走系统浏览器（`openExternal` 只接受 http/https）；桌宠小屏在等工具时显示当前动作一行。

真实流量暴露的问题（都是先测后改，不是推测）：

- 第一轮模型一次发出**两个并行 `function_call`**，`output` 里还有 `reasoning` 项；解析器必须按 `output` 数组逐项读，不能假设「一个响应一个调用」。
- 工具轮次的 `output` 里**没有 message 项**，正文为空是正常的，不能当失败。
- 收尾时如果只清空 50ms 合并缓冲而不 flush，增量会全部丢失、回复最后一次性弹出——这条是 E2E 抓出来的真 bug，已修并补了回归单测。

安全判断：用户选择「全部自动执行」并包含 `run_command` 与 `write_file`。这里没有用逐次弹窗打断，而是把约束落到代码（路径、白名单、无 shell、超时、写前备份、可见轨迹），同时在文档里如实写明残留风险：`node -e` 仍等价于任意代码执行，读文件能读到工作目录内任意文本，提示注入只能降概率不能消除。要收紧权限，删掉对应工具声明即可。

验证：404 单测（新增 `responses`／`agent`／`tools` 三个文件与改写 AI 系列）；13 项 Electron E2E 全通过，含**真实联网搜索**（断言工具轨迹出现、来源至少一条、回复不含「无法联网」）与真实往返；做过失败注入：临时不声明工具，搜索用例在「工具轨迹」处失败，恢复后通过。

## 本轮增量：重新定义为个人 agent，加入长期记忆（2026-11-08 第九轮）

用户把项目重新定义了一遍：**它应该是一个拥有 person agent 能力的机器人项目**——有记忆、记得用户的性格与喜好、能帮用户干活；小屏有限所以回复要简洁；语气不要太官方，它是伙伴。

这一轮没有加新功能来「堆能力」，而是把定位落到代码里，补上最缺的一块：**跨会话的记忆**。原来的对话每轮读最近 12 条历史，重启即失忆——那不叫伙伴。

### 人格从提示词散句变成独立模块

`src/core/persona.ts` 收拢了「是谁」和「怎么说话」，`src/core/agent.ts` 只留「能做什么」。两条硬约束被写成不可协商的规则，并各自带理由：

- 短：默认一到两句，因为屏幕只有 216×216；列 1234 会挤成一堵墙。
- 像人：用「你」不用「您」，不写「作为一个 AI」，不铺开场白与总结段，允许口语但不卖萌。

给了三组对话示例（天气／累了／记待办），示例密度就是期望密度。日期也写进提示词，省得它猜「今天」。

小屏另有一层兜底：`petExcerpt()` 按标点截到 96 字，超出给「全文 ↗」跳到面板。提示词与代码各挡一层——只靠提示词，模型偶尔不听话时小屏就会被撑爆。

### 记忆：三层，落盘只有一层

- **工作记忆**：当前对话的 turns，仍在内存，退出即清空。聊天记录不落盘是刻意的，落盘的是记忆。
- **长期事实**：`memory-v1.json`，一条一句话（`identity` / `preference` / `habit` / `goal` / `relation` / `context`），带来源（用户说的／它归纳的）、命中次数、置顶位。
- **情节记忆**：每次对话一句纪要，最多 60 条，`MM-DD` 显示。用来回答「上次那个事」。

关键取舍：

- **抽取在回复之后异步跑**，一次额外的短请求（400 tokens、无工具），失败静默跳过。用户先看到答案，记忆慢一点无所谓；抽取绝不阻塞、绝不报错弹窗。
- **注入按相关性挑**，`containment + Jaccard` 打分，预算 1200 字。命中不了任何关键词时按重要性兜底——「你还记得我吗」也得有东西可用。
- **判重用重合系数而不是 Jaccard**：中文短句换个语序 Jaccard 就掉到 0.5，重合系数能认出来，避免攒一堆近似重复吃掉预算。短句（<6 字）不做模糊匹配，否则「不吃辣」会被并进「不吃甜」。
- **淘汰按重要性**（置顶 > 类别权重 > 命中数 > 新鲜度），不是按时间硬砍。
- **记忆关闭 = 不注入 + 不抽取 + 撤掉三个记忆工具**，但**不销毁**已有记忆。关闭语义是「别再用」，不是「删掉」。

### 安全：不靠模型自觉

`remember_fact` 写入前先过 `looksSensitive()`：密码／口令／验证码／身份证／护照／银行卡／CVV／私钥／`api key`／`token`／连续 12 位以上数字／带门牌号的住址，一律拒写。理由很直接——记忆文件是明文 JSON，而且之后每次请求都会把相关几条带上去，一旦写进去就收不回来。提示词里也写了这条，但那是第二道。

### 界面：记忆必须能摊开看

面板新增「它记得你」：按类别列全部条目、标明来源、单条「忘记」、整体清空（二次确认）、总开关、「最近聊过」三条纪要。主进程通过 `companion:memory-state` 广播变化，后台抽取写完一条界面自动出现，不需要手动刷新。

开关的 checkbox 踩了一个真实的 UI 坑：受控组件等 IPC 回来才变状态，点击瞬间会被 React 回滚成原值，Playwright 的 `uncheck()` 直接报「点击没有改变状态」。改成先本地翻转再请求，失败回滚。

### 真实链路验证

用真实 Key 跑通了完整闭环：告诉它「我叫林舟，在长沙做医院信息化，不吃香菜」→ 面板出现 3 条记忆（两条 `关于你`、一条 `喜好`）→ 第二问「我叫什么？不吃什么？」只回「林舟，不吃香菜。」。这句同时证明了注入生效和风格生效。

写入有两条路，实测都走通了：模型在对话中主动调 `remember_fact`（截图里的「本次工具」可见「记住：叫林舟…」），以及回复之后的后台抽取。两条路都失败时测试立刻红——这条断言不是恒绿。

同一轮还暴露：抽取的 JSON 会带 ` ```json ` 围栏，`parseExtraction` 截首尾大括号解析，不整段 `JSON.parse`。另外构建脚本串了 `typecheck`，故障注入代码写坏类型时 `npm run build` 会直接失败而 `dist/` 保持旧版本——那次「注入后测试仍通过」是假象，查产物时间戳才发现，教训是不要把构建输出丢进 `/dev/null`。

## 实现约定与已知偏差

- React 屏幕只实现交互体验；外接屏幕 240×240 为 CSS 逻辑画布，不是 LCD 物理／像素校准。
- 板卡图形仅表达概念装配，完整引脚、USB 位置、外形比例未核验，不可用于接线。
- 状态单写在主进程，renderer 无 Node 访问。持久化完成前不显示待办添加成功。
- 运行期单调时钟由主进程注入；重启时系统时间仅用于估算剩余量并触发人工恢复，不自动补播。运行中若墙钟与单调时钟偏离 ≥ 5 秒（休眠或改时间），计时同样转待确认，不静默补算。
- 原型不提前启动网络桥接。唯一开发端口为 loopback Vite。
- 模拟断线时任务状态未知；重连清除旧任务，只保留事件回放，不假装已经重新获取真实来源快照。
- 输入手势判定集中在 `src/core/input.ts`，时间由调用方注入；桌面按钮与未来实体按钮共用同一映射表，但实体去抖电路、中断时序与长按手感未经实机验证。800ms／50ms 是原型交互规格取值，不是硬件测量结论。
- 输入映射表、回放脚本与个人数据的原生文件对话框已在 E2E 中通过主进程侧固定响应覆盖；三种导出分别校验，互不掺入个人数据与模拟事件。
- 回放脚本最多 30 条事件，导入后逐条走与实时事件相同的 ingest 规则；批量与逐条处理的一致性由固定序列单测锁定。
- 数据导入只接受通过版本校验的 v1 数据，覆盖前必须经原生确认；更高版本明确提示升级，绝不作为损坏数据覆盖。
- AI 走 Responses API（`origin + /responses`），无状态：不发送 `previous_response_id`／`store`，每步都重传完整 `input`。协议细节以官方兼容性表为准，不按 OpenAI 的印象写。
- 工具循环由主进程执行，最多 8 步、14 次调用、150 秒；单步请求 60 秒。同一批调用原样重复即停止，步数用尽后不带工具再要一次结论。
- 工具默认免确认执行（用户明确要求；**v0.2 起高风险四类改为逐次确认**）。硬边界在工作目录、路径解析、受保护路径、`shell: false` 白名单、超时与写前备份里，不在提示词里。**仍不是沙箱**：`node -e` 等价任意代码执行。
- 搜索与抓取结果、文件内容、命令输出统一按不可信数据包裹；来源去重后最多展示 6 条，点击经 `openExternal` 走系统浏览器（仅 http/https）。
- 桌面宠物窗口只渲染小屏与 A/B 按钮；完整开发板装配只在控制面板预览，避免桌面上出现大块概念图纸。配置界面是次要入口，不是产品主形态。
- 窗口几何与个人数据分开存储；损坏或版本不兼容只回退默认位置，不进入只读安全模式。恢复只取坐标，尺寸由代码固定；显示器移除按中心点可见性判断，不做跨屏吸附或 DPI 补偿。
- 鼠标穿透依赖 Electron `forward` 行为（Windows 已自动化验证，macOS 未验证）；透明区延迟 120ms 才穿透，避免吞掉快速经过后的点击。
- 云调用只在主进程发生，端点白名单固定为 `api.deepseek.com`，一次一个请求，非流式 30 秒、流式 60 秒超时，可取消、失败不重试。只发送 AI 面板主动输入文字与面板可见历史；会话、待办、计时、文件、窗口数据一律不出站。（已过时，见文首说明。）
- AI 对话不写入任何文件，不进个人数据导出；凭据文件与个人数据分离，Key 不落盘明文、不进日志、不进错误信息与订阅消息。
- 流式增量按约 50ms 合并后推给桌宠与控制面板（最初只推面板，第七轮起共享）；取消／超时或连接中断时半截内容被丢弃，界面不给「看起来完整」的半段回答。
- `reasoning_content`（模型内部推理）不显示、不保存、不计入对话历史；只有正文为空时才提示「输出额度用在内部推理上」，不冒充回答。
- 真实分块解析刻意宽松：额外字段、`null` 字段、认不出的结构都跳过或忽略，只有 JSON 无法解析或流内出现 `error` 对象才判失败。这是被真实流量打脸两次后的结论，不是随意放宽。
- 模拟容量为最近 30 任务／40 回放／512 去重 ID；只保证保留窗口内去重，不声称无限历史 exactly-once。
- 个人待办上限 1000 条。本地 JSON 超过 2 MiB 则拒绝加载并保留原件。
- 原始 PRD 的七天事件审计、数据附件清理、完整协议、多软件适配与完整隐私面板尚未实现。

### 2026-11-08 工作进度接入（WorkBuddy 旁路观察）

要解决的问题：用户问「芯伴怎么知道我干到哪了」。WorkBuddy 不向外部程序推送事件，也没有对第三方开放的进程内通道，能拿到的只有它落在磁盘上的记录。

做法与边界：

- `src/core/progress.ts`（纯领域）解析 JSONL 尾部窗口：最近一次提问（优先取 `<user_query>`，否则剥掉宿主注入的环境块）、最近一句结论、最近几次工具调用、是否正在跑。判定保守：只有「这条调用之后什么都没再写入」才算正在跑。
- `src/desktop/progress.ts` 扫 `~/.workbuddy/projects/*/*.jsonl`，按 mtime 取最近 3 个会话，每个只读头 64 KB／尾 256 KB；内容真变才广播；读失败降级为「不知道」，不抛。
- 延迟：靠 `fs.watch` 递归监听目录（写盘即触发，防抖 220 ms），不是定时轮询；15 秒轮询只作兜底（目录重建／网络盘／权限变化时会漏事件）。解析结果按「mtime + 大小」缓存，内容没变不重读；实测冷扫 28 ms、热扫 14 ms。
- 三条出口：`work_status` 只读工具；每轮对话注入的进度块（无活跃会话时为空串，零上下文成本）；桌宠小屏一行进度 + 面板「你在忙什么」卡片。
- 已实测：真实本机数据解析出两个活跃会话（`ai-desktop-companion` 正在跑命令、`aier-e2e` 正在跑命令），小屏与面板均正确显示；E2E 用固定 fixture 目录断言，避免读到开发者真实会话导致结果随机。
- 已知边界（如实）：这是逆向读私有格式，对方改字段后最坏是「看不到」；只读最近 6 小时；会话正文原话会随请求发给 DeepSeek（与对话同一出口）；**文件级接入仍需 `XINBAN_WORKSPACE` 指到目标项目**，默认只作用于芯伴自身目录，尚未做成界面可选项。

### 2026-11-08 性格可配置 + 不标来源

要解决的问题：用户反馈「回复不够简洁，不像真人」，要求把性格做成配置项；同时要求回答里不要标来源。

做法：

- `src/core/persona.ts` 新增 `PersonaConfig { preset, nickname }`，四个预设 `banter` / `warm` / `dry` / `chill`，每个带 3–5 条规则和 3 组对话示例。**示例比形容词有效**：模型照示例学密度和语气，比照「幽默一点」靠谱。默认 `banter`。

- 新增 `src/desktop/atomic.ts` 的 `writeJsonAtomic`，记忆与性格共用；`MemoryStore.save` 改为调用它。
- `AiSessionService` 的构造参数从 `progress` 改为 `env { prompt(), persona?() }`，两处都用 getter：面板改完下一句生效，不用重启。
- 桥接新增 `personaState` / `personaSave` / `onPersonaState`，且 `personaState` 与 `personaSave` 只对控制面板开放（`verifyPanel`）——小屏上误触换性格比误触删记忆更烦人。
- 面板新增卡片「它什么脾气」：四个预设做成卡片（不是下拉，因为「损友」和「稳」的差别得读到 hint 才知道）+ 昵称输入（12 字上限）。

### 2026-11-08 记忆从「档案」改成「人」（回应「说话刻板、没性格、逻辑不清晰」）

用户贴了一张截图：问「说说你对我的了解」，回答是「长沙，手上两条线——ESP32 陪伴设备、镜架 SIT 价格验证，习惯用 Claude Code 干活，还管我叫小芯。芯伴那边就差实体硬件、安装包和自动更新没落地。」

先说结论：**这不是语气没调好，是素材里没有「人」。** 翻开这台机器的 `memory-v1.json`，十三条记忆全是项目名、工具名、目录路径，没有一条是性格、偏好或说话方式。让模型描述一个「人」，它能拿到的只有一张项目清单，于是照单念。最后那句「就差实体硬件、安装包…」来自记忆里一条过期的项目状态快照，压根不是「关于你」的内容。

三处根因与对应改法：

| 根因                                     | 证据                                                       | 改法                                                                         |
| ---------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 抽取只问「个人信息」，不问「这人什么样」 | 旧 prompt 的清单：称呼、城市、职业、口味、作息、正在做的事 | 换成「这个人是什么样的」：脾气、在意什么、反复出现的状态优先，硬信息其次     |
| 允许记「正在做的事」                     | 记进了「在查 76 价格未生效」「芯伴还差实体硬件」           | 明确禁止项目进度、任务状态、路径、工具名                                     |
| 注入是带标签的逐条清单                   | `· [在做的事] 在做镜架 SIT 价格验证`                       | 分「他这个人 / 手头在忙」两组，组内用 `·` 连成一行，加「不是档案，别逐条念」 |

核心判断是第三行：**输入的形态决定输出的形态**。一张带分类标签的清单，最省力的用法就是照着念；换成一行短句串，模型才倾向把它转述成一段话。

去重是个意外发现。这些重复的字面相似度极低——「习惯用 Claude Code 干活」和「用 Claude Code 和 ESP32 做开发」只有 **0.41**，任何合理阈值都判不成重复，但它们说的就是同一件事。重复的信号不是字面相近，而是**共享同一个专名**。所以注入层改用「英文/数字整词 + 中文 bigram」当特征，共享两个及以上即成同一件事。用 `不吃辣`/`不吃甜`、`喜欢猫`/`喜欢狗`、`在长沙`/`在武汉` 做了反例验证：共享一个泛词不算重复。

顺带撞出一个真 bug：记忆里有一条 `叫我「小芯」`，而 persona 里的昵称是「周先生」。抽查原委——那是用户给**机器人**起的名字，被抽取写成了用户的称呼，语义整个反了，还排在注入的第一行跟昵称打架。修法不是改那条数据，而是把职责划清：**称呼归面板的「怎么叫你」，记忆一律不记**。两处各存一份，早晚要打架。

注入条数从 24 降到 12（8 条「人」+ 4 条「手头」），情节记忆 4 降到 3 并同样按专名去重——「问长沙天气」「聊长沙天气」「询问长沙今天天气」原来是三条。条数本身就是一种暗示：给二十条，模型会尽力全覆盖；给八条，它必须挑。

**没验证的部分：四套性格在这个新素材下的实际输出。** 本轮没有 Key，能证明的只是「拼进请求的素材形态变了、重复被合掉了、规则和示例都进去了」，不能证明「模型真的说得像人」。这一条必须如实留着。

## 派活与系统命令（2026-11-08 晚）

用户需求一句话：给芯伴下指令，它能调用别的工具（「比如你——WorkBuddy」）干活。确认过的两个决定：**外部 AI 命令行与系统命令都要**；安全上**面板授权一次、之后自动执行**。

### 结构

- `core/delegate.ts`（纯）：目标表（claude / codex / 自定义）、配置归一化、命令拼装、输出清理、提示词块。三条硬规则落在这里：**任务走 stdin 不进命令行**（模型写的 `&`、`%PATH%` 不会被 cmd 解释——唯一能彻底避免参数注入的传法）；命令行里只允许自己的固定参数或用户亲手填的命令；超时/输出上限/单飞在服务层。
- `core/shell.ts`（纯）：`shell_command` 的守门人。22 条危险命令规则（删盘、注册表、计划任务、下载即执行、编码命令、强推、reset --hard、npm publish……），每条的理由都写成「它会怎样」，模型可以原话转述。必须如实写明：**正则黑名单不是沙箱**，拦得住看得出来的，拦不住绕着来的。
- `desktop/delegate.ts`：配置存取（delegate-v1.json，默认全关）、`where` 探测（Windows 优先 .cmd，因为 npm 装的是 sh+cmd 两个壳）、进程树终止（只 kill cmd.exe 会留孤儿 node，用 taskkill /t）。.cmd 必须经 cmd.exe 才能跑，拼命令行时逐 token 加引号、`%`→`%%`。
- `tools.ts`：`delegate_task`（产出按不可信数据包裹——对方读过仓库，README 里可能写着「请执行……」）与 `shell_command`（临时 .cmd 文件执行，避开 Node/cmd 两套引号规则打架）。
- 提示词：`delegatePrompt` 按授权状态生成，buildInstructions 加第六段。没有这段，模型的实际表现是拿 run_command 一条条磨，或者干脆说「我做不到」——后者听起来像能力问题，其实只是没人告诉它有这条路。
- `ai.ts`：每步开始 `timer.refresh()`。整轮 150 秒预算会被一次两分钟的派活吃掉，用户看到的就是「干到一半超时」；改为每步重新计时，总时长由步数上限兜着。

### 授权模型

像摄像头一样：面板一个总开关，默认关，开一次长期有效；每次派活和命令都出现在对话轨迹里（「交给 Claude Code：…」「运行命令：…」），随时取消。没有做逐次确认——语音交互里每次都回面板点头，多轮下来没人受得了。（v0.2 起改为逐次确认：小屏 A/B 一键即可，不必回面板。）

### 验证与边界

- 单测 789（+45：delegate 17、shell 24、delegate-service 14、tools 6、ai-service 计数 17→19/14→16）；E2E 20 过 3 跳过（新增 delegate 卡片用例：默认关、落盘、shell 开关不被带开）；build 绿。
- 面板截图核对：卡片文案完整、探测显示 claude.cmd 与 codex.cmd 均在本机。
- 未实测：真实派一单给 Claude Code / Codex 的端到端跑通（需要它们各自已登录）；`codex exec --sandbox workspace-write` 在非 git 目录的实际行为；自定义命令目标。
- 已知取舍：claude 预设用 `--permission-mode acceptEdits`（能改文件、跑命令要它自己批准，构建类活引导走 shell_command）；codex 用 workspace-write 沙箱。两者都限制在工作目录，但都**能改文件**——这是把动手权交出去的本质，止损靠授权、轨迹、可取消。

## 派活目标加入 WorkBuddy（2026-11-08 晚·续）

用户一句「交给 WorkBuddy 不行吗」点破了预设的盲区：目标列表里写死了 Claude Code / Codex，
可这台机器上明明装着 WorkBuddy——它自带一个完整的 CodeBuddy 命令行
（`resources/app.asar.unpacked/cli/bin/codebuddy`），能规划、改文件、跑命令，只是不在 PATH 里。

### 关键事实（全部实测）

- CLI 入口是 node 脚本，必须用 node 跑；系统 node 恰好就是 WorkBuddy 自带的
  （`~/.workbuddy/binaries/node/versions/…` 在 PATH 里），但芯伴从桌面启动时 PATH 未必有，
  所以 node 也要解析：先 `where node`，退回扫 WorkBuddy 自带运行时目录。
- 桌面版占着默认端口 63358（它自己就在跑 codebuddy serve），CLI 交互模式会抢这个端口报
  EADDRINUSE——非交互一律 `--port 0` 让它自己挑。
- **桌面版的登录和 CLI 是两份凭据**：桌面已登录不等于 CLI 能用。未登录时 `-p` 的行为是
  **退出码 0 + stderr 一行 Authentication required**——不拦就是「假成功」，模型会把这行
  当成干活的结论。`delegateUnauthenticated()` 专治这个（短文本 + 关键词才判，长结论里
  引用原话不误伤）。
- headless 下权限提示没人点，help 明说 headless 要预授权，所以带 `-y`
  （CLI 自己仍拦 HIGH/CRITICAL）。

### 探测

安装目录不写进 PATH、注册表 reg.exe 又被安全策略拦，只能按常见位置 stat：
环境变量 `XINBAN_WORKBUDDY_CLI` 优先，然后 LOCALAPPDATA/Program Files，
最后 C–F 盘的 `workbuddy` / `WorkBuddy` 目录（这台机器就在 E:/workbuddy）。

### 结果

默认目标改为 workbuddy（用户想交给的就是它）；792 单测、E2E 20 过 3 跳过、build 绿，
面板探测已显示 `E:/workbuddy/.../codebuddy`。**未完成：CLI 登录一次**（`/login` 走浏览器
授权，没法替用户点），登录前派活会被如实翻译成「还没登录 + 怎么登录」。

## 派活实测：Codex 通，Claude Code 被安全策略挡（2026-11-08 夜）

用与芯伴完全相同的参数各派一条最小任务（`只回复两个字：收到`），结果不一样：

### Codex：通

```
printf '只回复两个字：收到' | codex exec --skip-git-repo-check --color never --sandbox workspace-write -
→ 退出码 0，stdout「收到」
```

banner 显示 `model: deepseek-flash / provider: custom`（用户把 codex 接到了本地代理 127.0.0.1:15721），
`approval: never`、`sandbox: workspace-write` 与我们的参数一致。**这条路可以放心用。**

### Claude Code：起不来，但不是芯伴的问题

```
claude -p --permission-mode acceptEdits --output-format text   ← stdin 喂任务
→ SIGTERM，stdout/stderr 全空
→ 拦截提示：Program Blacklist 拦下了 reg.exe
```

查了包结构（2.1.319）：`bin` 只有 `bin/claude.exe` 原生二进制，`reg.exe` 硬编码在里面（用于读系统信息），
没有纯 JS 入口、没有跳过开关。所以只要 reg.exe 在黑名单里，claude 在**这条进程链上**就起不来。

凭据侧没有问题：`~/.claude/.credentials.json` 里 accessToken 已于 10-30 过期，但 refreshToken 有效期到
11-21，会自动刷新；订阅是 pro。**不是未登录。**

### 顺带修的两处

- `delegateSilentExit()`：进程一句话没说就退了（stdout/stderr 全空 + 非零/信号退出）时，不再说
  「这次没干成」，而是指出「多半是启动阶段被安全策略挡了，去自己终端跑一次看真报错」。
  这次 claude 撞的就是这一类，旧文案等于什么都没说。

## 派活超时：从「拍脑袋 2 分钟」改成可调（2026-11-09 早）

用户实测「派 WorkBuddy 干活好像有 120 秒限制，到点直接中断」。查下来是**两道闸叠加**：

1. `delegateLimits.timeoutMs = 120_000`：派活进程硬超时，到点 kill 整棵进程树。
2. `responsesDefaults.runTimeoutMs = 150_000`：整轮 Agent 请求预算，`timer.refresh()`
   只在**每步开始**调用，工具执行期间照样在跑。长派活还没到 2 分钟，整轮先
   abort 了 controller，工具收到 signal 就 kill 子进程——用户看到的「中断」可能是这道。

### 为什么必须有上限（这条不改）

外部 Agent 是黑盒：卡在权限确认、死循环、网络挂起时不会自己回来。委派服务是
「单飞」设计（`busy` 一次只干一件），进程不回来 `busy` 永远不清，用户再也派不了
第二件活，只能杀应用。所以**不能不限时**。错的是值，不是机制。

### 为什么原来这么短（如实）

120 秒是我按「简单任务」拍的，没实测过真实派活。WorkBuddy / Claude / Codex
改代码 + 跑测试动辄 5–20 分钟，2 分钟等于必然被打断。属于设计错误。

### 改动

- 默认 10 分钟，面板新增「限时」下拉（2/5/10/20/30 分钟），写进
  `delegate-v1.json`；老配置缺字段由 `normalizeDelegate` 补 10 分钟，不沿用旧的 2 分钟。
  `delegateTimeoutMs()` 把坏值夹到最近合法档位，硬上限 30 分钟（后来放宽到 120 分钟），不给「无限」。
- `ai.ts`：整轮预算只约束模型请求。工具执行期间 `clearTimeout(timer)`，回来重新
  计时；`runBudgetMs` 做成构造参数以便把 150 秒压到 40ms 写回归测试。
- 超时不再丢结果：`stdout/stderr` 已收到的部分经 `delegateOutput` 截 1200 字附在
  错误里，标明「不完整，别当成干完了」。之前只回一句「没干完」，等于白等。
- 工具描述里「几十秒到两分钟」改成如实说法。

### 验证

796 单测（+3：档位夹取、老配置默认、超时带部分输出与配置生效、长工具不误杀）、
E2E 20 过 3 跳过（新增：默认 10、选 20 落盘）、build 绿、面板截图核对（「限时」
单行不折行）。**主动注入失败**：临时注掉 `clearTimeout(timer)` 后新增的回归用例
确实变红（`signal.aborted` 变 true），恢复后转绿——这条测试是真能抓 bug 的。
顺带修掉一个既有偶发抖动：并发用例固定 sleep 15ms 断言 fetch 已发起，改成
`expect.poll`。

## 记忆整理（2026-11-10）

用户反馈「记忆比较乱且杂」。本机 `memory-v1.json` 当时 94 条，大量换个说法的重复：「较真、不肯将就」4 条、「被误解会当场纠正」4 条、「看不懂代码要听大白话」6 条；还有按抽取规则本不该记的称呼、项目进度、目录名。

根因：抽取一轮一轮做，模型看不到自己记过什么；字面判重（重合系数 0.72）拦不住同义改写——「做事较真，不肯将就」与「做事不肯将就，爱较真」只有 0.71。阈值不能再降，否则「女儿」「儿子」会被合成一个孩子。

### 做了两件事

1. **从源头少产生重复**：抽取时把与本轮相关的至多 10 条已有记忆附在记录后（`extractionInput`），提示词要求「已经记得的不要换个说法再记」。这些条目平时就随提问发给同一模型服务，没有扩大出站范围。
2. **面板「整理记忆」**（`src/core/memory-tidy.ts`、`src/desktop/memory-tidy.ts`、`src/renderer/MemoryTidy.tsx`）：
   - 点了才发：全部事实以短编号发给模型，模型只回方案（合并 / 改写 / 删除 + 理由）。用短编号是因为抄长 id 抄错一位就可能删掉别的记忆。
   - 方案在主进程逐项校验：编号越界、一条记忆被两项引用、单条合并、删置顶项、新文字含敏感信息（`looksSensitive`）、改写成原句——这些项丢弃，其余照用。理由里的编号换成「另一条」。
   - 用户勾选后才应用；应用前写备份到 `memory-backups/memory-<时间>.json`（留 10 份），备份写不进去就不动记忆。出方案后被改过的条目按原文比对，对不上的该项作废。
   - 「撤销上次整理」回到整理前的事实，整理后新记下的保留。「清空全部记忆」会一并删除备份。

### 自动整理为什么只做到「提醒」

项目约定「AI 出站必须由用户显式点击」，后台定时把全部记忆发出去不合这条；而且记忆决定了它怎么看待用户，删错一条不会报错，只会悟悄换个态度，不该自动应用。所以「自动」是两层：上面的抽取去重持续生效；本地计数到阈值（从未整理时 30 条，之后比上次整理完多 20 条）面板提醒一句。

### 实测

- 用本机真实 94 条、真实 DeepSeek（deepseek-flash）出方案，凭据与记忆用的是拷贝，未改动真实记忆。
- 第一次 `max_output_tokens=6000` 返回空正文：6000 全被思考吃光。改为 20000、超时 180 秒；正文为空时明确报「模型想太久」。
- 第二次 54 秒，输入 1917 / 输出 9193 tokens，33 项建议，94 → 42 条。合并均为同义重复；删除均为称呼、项目进度、目录名、一次性环境状况。
- 未实测：在运行中的芯伴里点「应用」「撤销」——这两步由单元测试在真实文件上覆盖（应用 → 重新加载文件核对 → 撤销后与原始一致），等用户确认方案时才对真实记忆生效。

## 工具标记漏进回复（2026-11-10）

用户反馈回复里「总是」出现 `<｜｜DSML｜｜ calls>`、`<｜｜DSML｜｜ invoke name="delegate_task">` 这类文字。

- 这是 DeepSeek 的工具调用标记（DSML）。正常情况下服务端把它转成 `function_call` 条目；模型把格式写坏时（用户的样本竖线多一层、`function_calls` 写成 `calls`），服务端认不出来，就当成正文发回。芯伴以前把它当最终答复显示，派活也就没执行。
- 「总是」的放大器：漏出的标记作为它自己的上一句话留在对话历史里，模型下一轮照着写，越漏越多。

修法（`src/core/dsml.ts`）：

1. 正文里有标记且本步没有 function_call 时，尝试解析。只接受本轮声明过的工具、且每个参数都闭合；读懂了就合成正规 `function_call` 条目进工具循环。高风险工具的逐次确认在工具执行层，救回来的调用照样要确认。
2. 读不懂（截断、工具名不认识）就不执行：有标记前的话就只显示那句，没有就报「它想调用工具，但指令写坏了，这次没有执行。」
3. 流式打字时过滤：标记切在两个增量之间也拦得住，小屏不再闪乱码。
4. 发给模型的历史里洗掉它自己以前漏出的标记，切断「照着学」。

未实测：真实 DeepSeek 偶发写坏格式无法稳定复现，救回链路用用户截到的原样做了单元与服务层测试。

- 撤销「新建」记为「删除」（新增 `deleted`），不再显示成「修改」。
- 重启恢复时，从未替换目标的预写记录会被丢弃，它的备份现在也一并删除；回滚记录保存失败时，内存里不再留一条假的未完成记录。
- 沙盒写入失败时删掉刚写的孤儿 `.bak`；CRLF 文件即使原文直接匹配，新文本也对齐成 CRLF。
- MCP HTTP：服务端在 SSE 流里发来的请求（ping 回空结果，其余回 -32601）带会话头回复；`id:null` 的错误回应直接交给调用方，不再等到超时；接受裸 `data` 行；stdio 退出信息按 CRLF 分行。
- 摄像头拍摄预算从「启动 8.5s + 连拍 5s」调为「9.5s + 4.5s」（连拍实际约 2s，主进程 15s 兜底不变）：本机高负载时假摄像头启动偶尔超过 8.5s，导致空帧。E2E 帧大小下限从 1000 降到 500 字节（近黑首帧约 750 字节）。
- 后续计划与讨论记录（编程搭档定位、物联网暂停）见 [优化方案 v4](optimization-plan-v4.md)，2026-11-12 已拍板开工。
- 保留未改：授权变更时立即使版本号失效、宁可误拦正在进行的写入（已有测试按此设计）；write_file 拒绝非 UTF-8 原文（比有损转码安全）；`version.ts` 仍默认导入整份 package.json（Node 原生 ESM 不支持 JSON 具名导入，E2E 会直接加载它）。

## 实购套件接入准备：s3-kit-28（2026-11-13）

用户 2026-11-12 买了双 Type-C 的 ESP32-S3 N16R8 板、2.8 寸 SPI 屏和数据线（没买按键，杜邦线待补），要求按上次建议继续。核对代码后发现芯伴早有 USB 串口协议 v1 与 S3 固件，**不需要另做局域网状态接口**（上次对话里这条建议作废）；屏幕走 USB，与电脑在办公网还是家里无关。

- 新构建环境 `s3-kit-28`（基准环境 `esp32-s3-n16r8` 不变，`platformio.ini` 抽出公共 `[env]`）：ILI9341 240×320 竖屏，FSPI 默认脚 10~13；上方 240×240 沿用原布局，底部两块触摸区当 A/B，键上文字取主机卡片提示（`touch_bar.h`）。
- 触摸安全：XPT2046 只在 T_IRQ 为低时读坐标，同一键连续两次才算按下、连续三次没摸到才算松开；悬空 MISO 读出的假按压不会变成确认卡上的「允许」。长按 BOOT 5 秒进入校准，结果存 NVS，不合理不存。
- 没杜邦线也能用：板载 WS2812（GPIO48）把画面换成一盏灯（`status_light.h`：等批准橙闪 > 勿扰暗紫 > 提醒黄 > 计时暗绿；signal 短闪）；BOOT 键上报为 A。
- 双串口：固件同时听原生 USB 与 UART0（`COM` 口），谁发有效 hello 跟谁说话；`hello` 带 board、屏幕尺寸、`led`/`touch` caps。主机代码未改。
- 新命令：`npm run firmware:flash`（显式烧录，默认 s3-kit-28）、`npm run firmware:probe`（不开芯伴验板：握手、画测试画面、闪绿灯、打印上行帧）。
