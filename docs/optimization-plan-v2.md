# 优化方案 v2：从「应答式桌宠」到「守在你和你的 AI 们之间的伙伴」

- 日期：2026-11-09
- 状态：实施中（完成情况以文末「实施记录」为准）
- 前提：用户已确认——硬件走 **USB 串口优先**；高风险工具改为 **逐次确认**（A 允许 / B 拒绝）；动手前先做 git 本地基线。

---

## 0. 一句话

芯伴最值钱的不是「什么都能做」，而是**「安静地守在桌角，该开口时开口」**。
本轮只围绕三件事动刀：**信任**（先把会出事的地方堵上）、**主动**（它第一次自己找你）、**实体**（桌面版和硬件共用一套语义）。

## 1. 定位

| 层                   | 作用                                                                                                              | 本轮策略                                 |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| **工作伙伴**（核心） | 盯住你手上的 AI agent（WorkBuddy / Claude Code / Codex / 派出去的活），跑完、卡住、等你时主动说一句；待办到点提醒 | **加强**                                 |
| **陪伴**             | 有脾气、记得你、有仪式感（早安、收工、久别重逢）、会因为你干完活而高兴                                            | **加强**                                 |
| 通用助手             | 搜索、读写文件、跑命令、看屏幕                                                                                    | **收拢**：保留能力，但危险动作必须你按 A |

硬件的价值由此而来：一块桌角小屏 + 两个实体键，是 **AI 工作的状态灯和确认键**，而不只是会说话的摆件。

## 2. 设计原则（不可退让）

1. **主动开口不出站**：提醒由本地事件触发、本地台词生成（按性格预设），不自动调用 AI。用户按 A「细说」才发起一次 AI 对话——符合「AI 出站必须由用户显式发起」。
2. **打扰有预算**：每小时上限、同类冷却、勿扰时只排队不出声、被忽略的同类自动降频。
3. **安全在代码里**：逐次确认由主进程门控，不靠提示词；超时视为拒绝。
4. **一套语义两块屏**：桌面小屏与实体屏幕消费同一个 `DeviceView`；实体按键发原始按下/抬起，由主机用同一个手势状态机（`core/input.ts`）判定，固件不重写业务。
5. **模拟与真实分开**：没接硬件时可用「模拟设备」跑通协议，界面明确标注。

### W2 主动伙伴（核心新功能）

新模块 `core/proactive.ts`（纯逻辑）+ `desktop/proactive.ts`（接线）。

**事件源**（全部是已有信号，不新增采集）：

| 事件                                      | 来源                     | 示例台词（损友预设）                 |
| ----------------------------------------- | ------------------------ | ------------------------------------ |
| agent 会话停下（working → resting）       | 进度观察                 | 「Claude Code 那边停了，去瞧一眼？」 |
| agent 在等你（正在跑的工具是提问/审批类） | 进度观察                 | 「WorkBuddy 在问你话，别让它干等。」 |
| 派出去的活完成 / 失败                     | 派活服务                 | 「Codex 把活干完了。」               |
| 计时结束                                  | 状态服务                 | 「时间到，起来动一动。」             |
| 待办到期                                  | 状态服务（新增 `dueAt`） | 「「交周报」到点了。」               |
| 今天第一次见                              | 互动记录                 | 「早。今天还有 3 件小事。」          |
| 收工时段（18 点后首次）                   | 互动记录                 | 「今天划掉 4 件，可以了。」          |
| 久别重逢（≥3 天）                         | 互动记录                 | 「你可算回来了。」                   |

**打扰预算**：每小时最多 4 条；同一类 10 分钟冷却；同一事件只提一次；勿扰时不弹系统通知、不朗读，只在小屏排队；用户按 B 忽略的同类，冷却翻倍。

**呈现**：小屏出一张「它在跟你说」卡片（表情跟着事件变）；A = 细说（发起一次 AI 对话）或「好」，B = 知道了。面板「它主动说过的话」列最近 20 条与接受率。面板可整体关闭主动开口。

### W3 更有用

- **待办到期**：`todo` 增加可选 `dueAt`；面板可设置；`add_todo` 工具接受 `due`（ISO 时间）；小屏待办卡标出「今天 15:00」。
- **多 agent 观察**：进度源从 WorkBuddy 扩展到 Claude Code（`~/.claude/projects/**.jsonl`）与 Codex（`~/.codex/sessions/**.jsonl`）。解析逐字段容错，读不懂就是「不知道」。小屏工作行显示来源名。
- **今日小结**（本地）：划掉几件、专注几分钟、派了几件活。

### W4 更有趣（陪伴）

新模块 `core/bond.ts`：

- 相处天数、连续见面天数、摸摸次数、一起专注的分钟数——只存本机，可清空。
- 摸摸反应随亲密度变化（刚认识 → 熟了 → 老朋友），连续猛摸会「烦了」。
- 你划掉待办、计时完成、agent 跑完时它会高兴一下（庆祝表情）。
- 里程碑：第 7 / 30 / 100 天、第 100 次划掉待办——由主动引擎说一句。
- 上述信息以一行短句注入提示词（「你们认识 23 天了」），让 AI 说话也带上关系感。

### W5 硬件接入（USB 串口优先）

- `core/device-protocol.ts`：版本化 NDJSON 帧协议（Zod 校验）。
  - 主机 → 设备：`hello`、`view`（表情/标题/副标题/待确认/提醒/计时/工作行）、`signal`（LED/蜂鸣有界模式，AI 不能直接决定时长）、`ping`。
  - 设备 → 主机：`hello`（固件版本、屏幕尺寸、能力）、`button`（原始 down/up + 设备毫秒）、`pong`、`log`。
- `core/device-view.ts`：从应用状态算出 `DeviceView`，桌面小屏与实体屏共用。
- `desktop/device.ts`：`DeviceService` + 传输层接口；实现 `SimulatedTransport`（模拟设备，测试与面板用）和 `SerialTransport`（ESP32-S3 原生 USB CDC，按 Espressif VID `0x303A` 自动发现）。串口库不可用时静默降级，应用照常运行。
- 实体按键走与桌面同一套手势状态机与动作（确认/提醒/摸摸/勿扰）。
- 面板「硬件」卡：启用开关、连接状态、固件信息、模拟设备。
- `docs/hardware-protocol.md`：协议规格、推荐采购清单、接线待核验项；`firmware/` 放参考固件骨架（未在实机验证，明确标注）。
