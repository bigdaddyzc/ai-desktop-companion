# 实体设备协议 v1 与接入清单

> 功能状态统一见 [能力清单](capabilities.md)；真实硬件与串口驱动仍需实机验收。
> 实现：`src/core/device-protocol.ts`（帧与校验）、`src/core/device-view.ts`（画什么）、
> `src/desktop/device.ts`（连接、握手、心跳、按键）、`src/core/gesture.ts`（按一下会发生什么）。

## 1. 设计原则

- **传输无关**：USB CDC 串口优先；将来的 Wi-Fi/WebSocket、BLE 只需新增一个 `DeviceConnector`，帧格式不变。
- **设备只画与报**：固件按主机给的 `DeviceView` 画屏；按键只报原始 `down/up` + 设备毫秒。
  去抖、长按（800ms）、手势 → 动作全在主机，与桌面按钮是同一个状态机和同一张意图表。
  业务变了不用重烧固件。
- **安全边界**：设备上行帧一律 Zod 校验，坏帧丢弃不断连；设备不能触发 AI 出站，
  只能产生和桌面按钮等价的手势（确认/提醒卡上的 A/B 等同用户点击）。灯效/蜂鸣只有有限枚举，AI 输出不能决定。

## 2. 帧格式

一行一个 JSON 对象，`\n` 结尾（容忍 `\r\n`），UTF-8，**单帧载荷 ≤ 2048 UTF-8 字节（不含 LF/CRLF）**。串口 115200 8N1。
主机会自动压缩 `view` 帧中的长文本以满足上限。超长行、非 JSON、未知 `t` 一律丢弃。

### 主机 → 设备

| t        | 字段                                    | 说明                                                         |
| -------- | --------------------------------------- | ------------------------------------------------------------ |
| `hello`  | `proto:1, host:"xinban", v:"0.3.0"`     | 打开端口后立即发送；设备须在 3s 内回 `hello`                 |
| `view`   | `view: DeviceView`                      | 屏幕内容。内容不变不重发，变化时至少间隔 120ms               |
| `signal` | `pattern: nudge\|confirm\|happy\|error` | 灯/蜂鸣提示，只在卡片「新出现」时发一次；勿扰时不发          |
| `ping`   | `n`                                     | 每 5s 一次；设备回 `pong`。超过 15s 无任何上行即判断开并重连 |

`DeviceView`（详见 `device-view.ts`）：

```jsonc
{
  "v": 1,
  "mood": "idle|focus|busy|waiting|happy|sad|sleep",
  "face": { "eyes": "...", "brows": "...", "mouth": "...", "extra": "...", "blush": false }, // 可为 null
  "title": "在陪你",
  "detail": "不用着急",
  "corner": "14:05", // 或「勿扰」
  "quiet": false,
  "card": null, // 或确认卡 / 提醒卡，见下
  "timer": { "label": "专注中", "remaining": "18:20" }, // 可为 null
  "todo": { "title": "交周报", "more": 2, "due": "今天 18:00" }, // 可为 null
  "work": "Claude Code app · 读文件",
  "bubble": "",
}
```

卡片（有卡时固件应优先画它，并在屏底显示 `A {hintA} · B {hintB}`）：

```jsonc
{ "kind": "confirm", "id": "c1", "title": "要跑一条命令", "detail": "npm test", "seconds": 42, "queued": 0, "hintA": "允许", "hintB": "拒绝" }
{ "kind": "nudge", "id": "n1", "text": "Codex 停了。", "mood": "idle", "hintA": "细说", "hintB": "知道了" }
```

### 设备 → 主机

| t       | 字段                                                                 | 说明                                        |
| ------- | -------------------------------------------------------------------- | ------------------------------------------- |
| `hello` | `proto:1, fw, board?, screen?{w,h}, buttons?["A","B"], caps?["led"]` | `proto` 不一致时主机报错并停止写入          |
| `btn`   | `b:"A"\|"B", e:"down"\|"up", ms`                                     | `ms` = 设备开机毫秒（`millis()`），单调递增 |
| `pong`  | `n`                                                                  | 原样回传                                    |
| `log`   | `level?:info\|warn\|error, msg(≤200)`                                | 显示在面板「伙伴与设备 → 硬件」里           |

允许多余字段（固件升级可加东西）。

### 物联网扩展帧（v1 内的可选能力）

设备在 `hello.caps` 里声明 `"iot"` 后，主机才会发这些帧；不声明的固件不受影响。
ESP32 是中枢：自己连 Wi-Fi、轮询设备、执行开关；登记表存在 NVS，电脑关机时用实体按键照样能控制。

| 方向      | t            | 字段                                         | 说明                                                                 |
| --------- | ------------ | -------------------------------------------- | -------------------------------------------------------------------- |
| 主机→设备 | `iot.config` | `devices:[{id,name,kind,host,ch}]`（≤ 8 台） | 握手后与每次登记表变化时发；设备覆盖写入 NVS                         |
| 主机→设备 | `iot.set`    | `id, on:boolean`                             | 只由面板里的用户点击触发；AI 对话没有控制电源的工具                  |
| 设备→主机 | `iot.state`  | `id, online, on?, w?(瓦), err?`              | 状态变化立即报，没变也每 10s 报一次；主机 20s 没收到就显示「不确定」 |
| 设备→主机 | `iot.net`    | `ok, ssid?, ip?, rssi?, portal?`             | 没连上 Wi-Fi 时带上配网热点名                                        |

`kind` 与局域网接口（都不经过云、不要账号）：

| kind      | 查询                                          | 开/关                                          | ch                            |
| --------- | --------------------------------------------- | ---------------------------------------------- | ----------------------------- |
| `tasmota` | `GET /cm?cmnd=Power{ch}` → `{"POWER":"ON"}`   | `GET /cm?cmnd=Power{ch}%20ON`                  | 空或 1~8                      |
| `shelly`  | `GET /rpc/Switch.GetStatus?id={ch}`（含功率） | `GET /rpc/Switch.Set?id={ch}&on=true`          | 0~3（Shelly 第二代 Plus/Pro） |
| `esphome` | `GET /switch/{ch}` → `{"state":"ON"}`         | `POST /switch/{ch}/turn_on`（需开 web_server） | 开关实体 id                   |

安全边界：主机只接受局域网地址（私有 IPv4 或 `xxx.local`），`ch` 按类型白名单校验，中枢不会被配置去访问公网。
Wi-Fi 密码由 WiFiManager 配网门户在手机上填，**不经过电脑、不进芯伴的任何文件**。
上述三种接口按各自官方文档编写，**都未在真实设备上验证**；Tasmota/ESPHome 若设了 Web 密码需另加鉴权（未实现）。

独立运行（未握手，或 15s 收不到主机有效 hello/ping/view 帧）时，固件自己画设备列表：A 短按选下一台，B 短按开/关。
接回电脑后按键自动恢复成「只报原始边沿」。

## 3. 按键语义（与桌面一致）

优先级：`B 长按 = 勿扰` → `A 长按 = 未分配` → 确认卡（A 允许 / B 拒绝）→ 提醒卡（A 接 / B 知道了）
→ 模拟任务确认 → A 摸摸 / B 小游戏。确认卡 60s 无人回应视为拒绝。
外部 Agent（Claude Code / WorkBuddy）的权限请求（远程批准，2026-11-12）沿用同一种确认卡帧，不新增帧类型：
A 允许 / B 拒绝不变，24 字内可打印 ASCII 才能在设备上允许；`seconds` 倒数到 0 时交回终端（不是拒绝）。
「交回终端」「以后同类都批」只在桌面上有。

## 4. 主机侧行为

- 固件同时听原生 USB（`Serial`）和 UART0（`Serial0`，双 Type-C 板的 `COM` 口），谁发来有效 `hello` 就只跟谁说话，另一个口只听 `hello`（2026-11-13）。
  `hello.caps` 可能含 `led`（板载彩灯，把画面换成一盏灯）和 `touch`（竖屏底部 A/B 触摸键），主机不依赖它们。
- 自动找端口：优先 Espressif 原生 USB（VID `303a`），其次 CP210x `10c4` / CH340 `1a86` / FTDI `0403`。
  面板可指定 `COMn`。打开时 `hupcl:false`、DTR 拉高、RTS 拉低，尽量避免把 ESP32 复位进下载模式
  （**各开发板自动下载电路不同，需实机验证**）。
- 握手 3s 超时 → 关闭端口、3s 后重试；不会对未握手的设备写 `view`。
- 拔线 / 心跳超时 → 状态回到「正在找设备」并自动重连；桌宠不受影响。
- 串口库 `serialport@13`（N-API 预编译），按需动态加载；加载失败只影响「硬件」一栏。
- 面板可切到「模拟设备」：不接硬件跑通握手、镜像画面、模拟 A/B。

## 6. 待实机核验（买到硬件后逐条做）

1. Windows 是否自动识别 CDC 端口；CH340 板是否需装驱动。
2. `serialport` 在打包后的 Electron 45 里能否加载（Node 下已验证可列端口，Electron 内未验证；打包时需把它放进 asar unpack）。
3. 打开端口是否导致板子复位；复位后固件是否仍能在 3s 内回 `hello`。
4. 屏幕引脚（MOSI/SCLK/CS/DC/RST/BL）与按键 GPIO，避开 S3 的 strapping 脚（GPIO0/3/45/46）和 PSRAM 占用脚。
5. 中文字库体积与刷新速度（建议只带常用 3500 字的 16px 点阵字库）。
6. 按键机械抖动是否在 50ms 去抖窗口内。

固件工程见 `firmware/xinban-device/`，固定构建入口和引脚见 [硬件基准](hardware-baseline.md)。编译与自动化测试状态统一见 [能力清单](capabilities.md)；**尚无实机烧录与运行验收**。

## 7. 第一阶段补充约束（2026-11-11）

- 单帧上限是 **JSON 载荷 2,048 UTF-8 字节**，不含 LF/CRLF；空白和未知扩展字段也占预算，不按 JavaScript 字符数计算。
- 收到超长行后必须丢弃直到下一换行，再接收新帧；不能把超长行的尾部误识别成按键或命令。串口 UTF-8 解码须跨分包保留状态。
- 固件回应 hello 并检查 proto；未握手或宿主过期不处理业务帧。错误帧、signal 和 IoT 命令不延续主机心跳。
- `DeviceView.face` 的 eyes/brows/mouth/extra/blush、work、bubble、确认 seconds/queued 均属于显示契约。中文使用固定 U8g2 字体，测宽换行、超出行数省略；不支持的非 BMP 字形显示 `?`。
- **小屏批准条件**：详情不超过 24 个单行可打印 ASCII 字符；中文、多行、控制字符或更长内容仅预览，A 转桌面看全文，B 仍可拒绝。主机 `ConfirmService` 独立强制这一规则，不能只信屏幕提示。
- 共享测试语料是 `tests/fixtures/device-contract.json`：TypeScript 检查线上字节与分包，C++ 本机程序调用固件使用的接收器和布局代码。它们不等于真实 SPI 屏幕、Wi-Fi 或 FreeRTOS 测试。
