# 芯伴 vs Grok Bot：能力差距评估

日期：2026-11-10。

## 先说证据的分量

- **芯伴**：以 [能力清单](capabilities.md) 为准，分「已实测 / 只有自动化测试 / 未做」。行为质量有评测集数字（45 题×2 轮 98%）。
- **Grok Bot**：来自对本机 Grok Bot Desktop 0.75.0 客户端的静态分析——它是一个薄 Electron 客户端（基于 Cursor 的代码底座），智能体、工具、模型都在云端（沙箱 + 工作流引擎），客户端通过 `aiserver.v1.GrokBotService` 的 291 个 RPC 说话。**下面对 Grok Bot 的能力是从接口名和协议定义推断的，没有逐项上手用过**；「接口里有」不等于「好用」，也不等于已对所有用户开放。

## 一句话结论

**两者不在一个量级，也不在一个赛道。** 按「能力面」算，芯伴大约覆盖 Grok Bot 的 15–20%；但在「本机、私人、盯你自己的 AI 编码工具」这一小块上，芯伴是 Grok Bot 没有的。Grok Bot 是「云端全能助理平台」，芯伴是「桌上的本地管家 + 编码 Agent 调度员」。

## 差距里哪些值得追、哪些不该追

不该追：团队协作、花钱、群聊、生图。它们和「桌上的私人伙伴」无关，追了只会让芯伴变成一个更差的 Grok Bot。

值得追（按投入产出比排序，建议作为下一轮的候选，本轮不做）：

1. **MCP 客户端**：芯伴一旦能连 MCP 服务器，邮箱、日历、浏览器（Playwright MCP）、文件系统等生态工具就都能接进来，一次补上「连接器」和大半「浏览器操作」的差距。沿用现有确认门：每个 MCP 工具按风险分级，高风险的逐次确认。
2. **可选更强的模型**：简单问答继续用 deepseek-flash（快、便宜），多步任务切到更强的模型。评测集已经可以量化切换的收益。
3. **定时任务**：「每天 9 点看一眼各项目的 CI」「每周五把本周派活记录总结一下」——用现有的主动开口 + 派活就能拼出来。
4. **发行链路**：安装包、签名、自动更新。不加功能，但决定它能不能给别人用。

芯伴应该继续加深的护城河：**你本机各个编码 Agent 的总调度 + 状态感知 + 安全门**。这是云端助理结构上做不到的——它们看不到你电脑上的 Claude Code 在等你确认。
