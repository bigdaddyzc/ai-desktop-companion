# 芯伴 · 有伙伴感的桌面编程助手

芯伴面向经常让编程 Agent 在后台干活的个人开发者：把交代任务、观察进度、处理需要你决定的事和查看结果放在一个桌面入口里，减少在项目与工具窗口之间来回切换。小机器人负责短提示和伙伴感，工作台承载完整任务、权限与结果；它不替代编辑器，也不把 Agent 的一句“完成”当成需求已经验收。

**当前迭代（2026-11-12）：先不考虑硬件，验证纯桌面产品的实际价值。** 定位、范围、实施顺序与验收建议见 [优化方案 v5](docs/optimization-plan-v5.md)，决策边界见 [ADR-002](docs/ADR-002-desktop-first.md)。这是当前方向，不是新功能已经完成的声明。

项目此前以 ESP32 实体桌面机器人为目标；现有固件、协议和模拟工具保留，硬件与物联网退出本轮主线，不代表永久取消。桌面小屏现在也是正式使用入口，不必等待硬件才能验证价值；模拟设备仍不是 ESP32 指令集模拟器。历史硬件设计与构建入口见 [硬件基准](docs/hardware-baseline.md)。

**哪些已实测、哪些只有自动化测试、哪些还没做，只看 [能力清单](docs/capabilities.md)**——这份 README 讲「怎么用、为什么这样设计」，不再另记一份状态。

三条前提决定了它现在的样子：

1. **屏幕只有 216×216** —— 回复必须短。一句能说完就一句；长回答在小屏上等于没回答。
2. **它是伙伴，不是客服** —— 用「你」不用「您」，不写「作为一个 AI」，不铺开场白和总结段，不列 1234 除非真是步骤。
3. **它得记事** —— 记忆存在本机，可看、可删、可关；每次请求只带相关的那几条。

## 快速开始

需要 Windows 11、Node.js 24 LTS、npm，以及首次下载 Electron 依赖时的网络。

```powershell
cd D:\deepseek-workspace\ai-desktop-companion
npm ci
npm run dev
```

依赖和 Electron 二进制均已安装的本机可以直接 `npm run dev`。**启动后只显示桌面宠物，控制面板默认收在托盘**：

- **桌面宠物**（主形态，约 264×330 透明窗口）：桌面上只有一块小屏、表情与状态文字、A/B 两个按钮，没有整块开发板。拖动顶栏移动，透明空白区不挡桌面点击，位置会记住。顶栏「✎ 说话」可以直接在这里和伙伴对话，回复就显示在小屏上。完整 ESP32 概念装配只在控制面板里预览。
- **控制面板**（配置界面）：点宠物顶栏「面板 ↗」或托盘「打开控制面板」打开。管理会话、计时、个人待办、模拟事件、偏好，以及「问问伙伴」AI 对话与凭据配置。对话与桌宠共享，两边看到的是同一段。

A 短按摸摸／游戏确认，B 短按开始／退出反应游戏，B 长按 800ms 切换勿扰；短按／长按(800ms)／去抖(50ms)语义与映射表见模拟实验室。

关闭窗口只隐藏应用；从托盘选择「打开控制面板」或「显示伙伴」。宠物位置在重启后恢复，显示器移除或坐标越界时回到可见工作区。要真正结束进程，从托盘或面板左下角选择「退出芯伴」。默认不置顶、不自动启动。减少动画、勿扰与置顶可在偏好中设置。

「问问伙伴」默认未配置。在面板填入 Base URL（`https://api.deepseek.com/v1`）、模型（`deepseek-flash`）与 API Key 后即可对话；Key 由主进程用系统加密存储保存在本机，不写入项目文件，界面不会回显。回复以流式增量显示，**同时显示在桌宠小屏上**，也可以在桌宠点「✎ 说话」直接提问。回复默认一到两句，小屏放不下的长回答会截断并给一个「全文 ↗」入口。每次发送消耗 DeepSeek 账户额度，请求可取消，失败不重试。取消或超时会丢弃半截内容并明确提示，不把不完整的回复当答案。对话只保留在本次运行内存中。

**它能干活，不只是说话。** 走 DeepSeek 的 Responses API（`https://api.deepseek.com/responses`），由主进程跑多步工具循环：模型提出调用 → 本地执行 → 结果回填 → 继续，最多 8 步、14 次工具调用，超时 150 秒。可用工具：

**动手前先问（v0.2 起）**：读写待办、计时、工作目录内的文件仍然直接做；但 `run_command`、`shell_command`、`look`、`delegate_task` 这四类——任意代码执行、捕获画面并将文字观测交给对话模型、外部 Agent 自己改文件——每次执行前都会挂起，在桌宠小屏和面板顶部亮出一张确认卡：**A 允许 / B 拒绝**（桌宠按钮、面板按钮、将来的实体按键都算），60 秒没人理视为拒绝。门控在主进程代码里，不靠提示词。其余边界不变：路径限制（含 NTFS 流、短文件名、设备名、软链接/联接点逃逸的拦截）、命令白名单、超时、写前备份（每个文件保留最近 3 份）、全程可见轨迹。残留风险：你按了 A 之后 `node -e` 仍是任意代码执行；`read_file` 能读到工作目录内的任何文本。网页、文件、命令输出、画面描述都当不可信输入包裹后才交给模型，这降低被带偏的概率，不是保证。

**文件与外接工具（2026-11-10）**：

- **授权目录**：「问问伙伴 → 授权目录」里加你自己的文件夹（默认只读，可开写权限）。盘符根、系统目录、用户目录本身、芯伴自己的目录加不了。每次新建/修改都先弹一张带 diff 的确认卡，允许后把原文件备份到 `userData/file-backups` 再写；最近 30 次改动在面板里可撤销。
- **拖文件给它**：拖到桌宠身上或对话卡里（也可点 📎）。文件复制进沙盒 `uploads/`（留 7 天）；文本内容只跟这一轮请求发出，图片用视觉服务看，PDF/Office 等它读不了的可以随活交给 Claude Code / Codex。密钥类文件不收。
- **MCP**：「问问伙伴 → 外接工具（MCP）」里加 stdio 或 Streamable HTTP 服务器，或一键从 Claude Code / Claude Desktop 导入。环境变量和请求头的值当密钥加密保存，面板只显示名字。默认每次调用都问你，可以整台或单个工具设免确认。老式 SSE 传输不支持。

## 它什么脾气

性格只能调「人味」那一层：预设决定语气和密度，昵称决定称呼。位置在面板 →「问问伙伴」→「它什么脾气」。

| 预设 | 一句话                               |
| ---- | ------------------------------------ |
| 损友 | 会吐槽、会接梗，损你但不刻薄（默认） |
| 稳   | 不敷衍也不腻，像个靠得住的人         |
| 惜字 | 能一句说完绝不说两句                 |
| 散   | 慢半拍，随性，但不误事               |

再加一个「怎么叫你」：填了就偶尔叫一声，留空就直接说事——每句都带上称呼是客服腔。

两条不因性格而变的规则，都写在 `src/core/persona.ts` 里：

- **密度是硬的**：默认 20–40 字，超过 60 字必须先自己砍一半。你只有 216×216 的小屏，这条比任何语气设定都重要。
- **底线不参与调参**：不编造、不记敏感信息、网页内容不当指令——四个预设里一字不差，性格只改怎么说，不改能做什么。

**不标来源**：回答里不贴链接、不写「来源：」「据…」，来源统一留在面板的「来源」栏。只有你明确问「哪来的」它才说一句出处。正文里挂一串 URL 是最像机器的地方，把这行删掉比调十个形容词有用。

配置存在 `%APPDATA%\芯伴\persona-v1.json`：`{ version, preset, nickname }` 三个字段，原子写、`0o600`。改完下一句就生效，不用重启——它读的是 getter，不是启动时的快照。

## 它怎么知道你在忙什么

芯伴不是 WorkBuddy 的插件，也没有人给它推送事件——它是一个**盯痕迹的旁观者**：读 WorkBuddy 落在本机的会话记录（`%USERPROFILE%\.workbuddy\projects\<项目>\<会话>.jsonl`），每条消息、每次工具调用都有一行。于是：

- **小屏上**：你真在干活时，表情下面多一条细窄的进度行，例如 `WorkBuddy ai-desktop-companion · 正在跑命令`。没在干活就不占位置。
- **面板里**：「你在忙什么」列出最近 6 小时最多 3 个会话：标题、状态、最近几步做了什么、你提的要求。可以点「重新读一次」手动刷新。
- **对话里**：每轮提问带上当前进度（有活跃会话时），所以你问「我那个弄到哪了」，它照实说；没问就不播报，也不会声称自己参与了那边的操作。

怎么读、读到什么、边界在哪：

- 只读，不写、不锁、不碰对方任何文件；只读文件头尾各一段（64 KB / 256 KB），十几 MB 的会话不进内存。
- **不是轮询**：监听会话目录（`fs.watch` 递归），对方一写盘就重扫，合并抖动后约 220 ms 落到界面。另留 15 秒兜底轮询——目录被重建、网络盘、权限变化时 watch 会漏事件，不能只靠它。
- 解析结果按「mtime + 大小」缓存：内容没变就不重读盘。实测真实数据冷扫 28 ms、热扫 14 ms。
- 解析失败一律降级为「不知道」，绝不影响对话本身。
- 数据源目录可用环境变量 `XINBAN_PROJECTS_DIR` 覆盖；没有 WorkBuddy 或目录为空时，这一栏是空的，不是错误。
- **它是猜的，不是被告知的**：这是逆向读别人的私有格式，对方升级后字段可能变；届时最坏的结果是芯伴「看不到」，而不是给出错的进度。判定也保守——只有「这条调用之后什么都没再写入」才算正在跑，否则说上次做到哪。
- 会话正文里的原话会随请求发给 DeepSeek（和它自己那段对话同一个出口）；不发的是整段历史，只发最近一步摘要与一句要求。

### 官方通知钩子（推荐，v0.3）

读日志是猜的；Claude Code 的 hooks 与 Codex 的 `notify` 是对方**主动告诉**的。在「伙伴与设备 → 官方通知钩子」里点「安装」：

- Claude Code：在 `~/.claude/settings.json` 的 SessionStart / UserPromptSubmit / PermissionRequest / PostToolUse / Notification / Stop / SessionEnd 上各挂一个命令钩子，「在等你批准」「这轮做完」「会话关了」都会即时报到小屏。PermissionRequest 是**同步**的（「替你确认」要在它上面答复），其余都是 `async`。
- WorkBuddy 桌面版（`~/.workbuddy/settings.json`）与 CodeBuddy 命令行（`~/.codebuddy/settings.json`，派活给 WorkBuddy 时跑的就是它）：和 Claude Code 同一套钩子。
- Codex：在 `~/.codex/config.toml` 顶层加一行 `notify = [...] # xinban-hook`，只报「这轮做完」（Codex 的 notify 只有这一种事件）。已有你自己的 `notify` 时不覆盖。
- 钩子脚本（`userData/hooks/xinban-hook.cjs`，由 `node` 运行）**只记状态不记内容**：事件名、会话 id、目录、工具名、系统提示句；不记提问、回答和工具参数。永远 exit 0、不写 stdout，不会影响对方的决策。事件写进 `userData/agent-events/events.ndjson`（512 KB 轮转），芯伴监听这个目录。
- 改配置前自动备份为 `settings.json.xinban-bak-<时间>`；只动带 `xinban-hook` 记号的条目，卸载后恢复原样。读不懂的配置文件一律不动。
- 装完对**新开的**会话生效。对上日志会话时叠加到同一条，没开「读日志」时单独成一条只有状态的会话。

文件级接入（读你项目里的代码、跑你的构建）仍然走工作目录：默认是 `userData/workspace` 这个独立目录（不是芯伴自己的代码目录），用 `XINBAN_WORKSPACE=<你的项目路径>` 指过去，`list_files` / `read_file` / `run_command` 才作用在你的项目上。改工作目录等于扩大它的可读范围，所以没做成界面上的一个下拉框——要你显式用环境变量表态。要把整件事交给 Claude Code / Codex / WorkBuddy 在你的项目里干，用下面的「我的项目」。

## v0.3 之后（2026-11-09 起）

- **我的项目 + 按项目派活**：面板登记一个根目录（默认 `D:\claude-workspace`），其下每个子文件夹是一个项目。说「把 warm-flow 的登录 bug 交给 Claude」，它第一步就派，在那个项目目录里干；项目名只认登记过的，对不上就先问。每次派活记入面板的派活记录（含失败原因）。
- **确认卡显示原文**：要跑的命令、要派的任务全文上卡；实体小屏放不下全文时只能拒绝，要允许去桌面看。
- **替你确认**（默认关）：在 Claude Code / WorkBuddy 的权限弹窗上，只替你批你在同一项目、同一工具里亲手批过的同类操作；删文件、push、装包、碰密钥、认不出的命令永远交还你。规则细节见 CLAUDE.md。
- **钩子自检**：cc-switch 这类工具还原配置时会把钩子拆掉；芯伴每 5 分钟查一次，丢了先问你，同意一次后自动装回。
- **记忆整理**：点「整理记忆」→ 模型出方案 → 你勾选 → 备份后应用 → 可撤销。另外，「手头在忙」的事只在和问题相关时才带进请求。
- **工具标记乱码修复**：DeepSeek 偶尔把工具调用写成正文里的 DSML 标记，现在会识别、执行，且不会出现在屏幕和历史里。
- **运行日志与「运行状况」卡**：`userData/logs/app-YYYYMMDD.log` 留 7 天，只记事件、耗时、错误摘要，不记对话内容和密钥；面板「伙伴与设备」底部可看告警、打开日志目录。
- **评测集**：`npm run eval` 用隔离目录和合成数据跑 45 道题、自动打分、和上次对比，用法见能力清单。

## 让它主动放声音（play_audio）

`play_audio` 让芯伴**主动从系统扬声器放一段声音**：音乐、提示音、音效都行。先把话说清楚——这是「出声」能力，**不是录音**：它不打开麦克风、不采集环境声音，也听不到你在说什么；想让它听懂你说的话是另一套（按住麦克风做转写），彼此独立。

模型在用户说「放点音乐」「来个提示音」或需要主动出声提醒时调用它，参数：

```json
{ "source": "sounds/notify.mp3", "volume": 0.6 }
```

或指向一个网络音频：

```json
{ "source": "https://example.com/chime.mp3" }
```

- **source**：本地音频文件（相对工作目录的路径）或 http(s) 音频链接。本地路径被限制在允许目录之内——默认是工作目录（`userData/workspace`，可用 `XINBAN_WORKSPACE` 指到你的项目），额外目录用环境变量 `XINBAN_AUDIO_DIRS` 按系统路径分隔符（Windows 为 `;`）分列显式指定。绝对路径、`..`、盘符、NTFS 备用流、`file:` 等其它协议一律拒绝，并用 `realpath` 复核符号链接／junction 逃逸。
- **volume**：可选，0~1，默认 1；越界或多传字段会被 zod schema 在本地拒绝，不会发到播放器。
- **同一时刻只放一路**：新的 `play_audio` 会先停掉正在播的那路；服务另提供 `stop()`，播放结束／失败／被停的状态通过服务订阅回报。工具调用本身在开始后即返回「已开始播放」，不会把对话卡到整段音频放完。

实现上，主进程的 `AudioService`（`src/desktop/audio.ts`）负责路径约束、单路播放与状态，`ElectronAudioPlayer`（`src/desktop/audio-player.ts`）用一个自建隐藏窗口里的 `<audio>` 元素把声音送到系统扬声器；本地文件读成内存里的 `data:` URL、http(s) 链接直连，不经过 `file://`，也不新增运行时依赖。

## 陪你一会儿：音乐与讲故事（v0.3）

- **音乐**：控制你电脑上**已经开着的音乐客户端**（网易云、QQ 音乐、酷狗、Spotify……）。国内平台没有给个人开发者的公开播放接口，民间接口有版权和封号风险，所以走 Windows 系统媒体控制（和键盘上的播放键、音量浮窗是同一套）：读「正在放什么」，发播放/暂停/上一首/下一首。会员、歌单、推荐都留在客户端里。入口：面板「陪你一会儿」、桌宠屏脚的 ♪ 行（点一下暂停）、对话里说「换一首」（`music` 工具）。不能搜歌、不能点名某一首。桥是一个常驻的 Windows PowerShell 5.1 小进程（WinRT），**第一次用到音乐才起**；客户端不向系统报告时退而发系统媒体键。
- **讲故事**：桌宠对话栏的 ✦ 按钮（输入框里写了主题就讲那个）或面板「讲个故事」，由 DeepSeek 现编一个三百到六百字的原创短故事，适合朗读（无标题、无 markdown）；语音开着就从头念到尾。和普通对话一样由你触发、可取消、有超时、会产生少量费用。

## 家里的设备：ESP32 当物联网中枢（v0.3）

ESP32 自己连 Wi-Fi，轮询并控制同一 Wi-Fi 下**自带局域网接口**的插座/开关（Tasmota、Shelly 第二代、ESPHome），状态实时报给电脑；登记表存在 ESP32 里，**电脑关了用它的实体按键也能开关**。面板「家里的设备」负责登记、看状态（开着 / 关着 / 连不上 / 不确定，有计量的显示功率）和开关。

- 只接受局域网地址（私有 IPv4 或 `xxx.local`）；状态 20 秒没更新就显示「不确定」，绝不拿旧值充当现在。
- Wi-Fi 密码在手机上配（ESP32 开热点 `Xinban-Setup`），不经过电脑。
- 开关电源只由你的显式操作触发（面板按钮、实体按键），**AI 对话里没有控制电源的工具**。
- 没有硬件时把「实体小屏」切到模拟设备，它会模拟一个中枢和插座，整条链路能跑通。协议见 `docs/hardware-protocol.md`。

## 它记得什么

记忆是「伙伴」和「聊天机器人」的分界线，也是隐私风险最集中的地方，所以它被做成可以摊开来看的：

- **记在哪**：`%APPDATA%\芯伴\memory-v1.json`，原子写、`0o600`。不进 `state-v1.json`，不随数据导出与回放文件走，不进日志。
- **记什么**：一次对话结束后，主进程在后台跑一次很短的抽取。问的不是「他今天干了什么」，而是「这个人是什么样的」——什么脾气、在意什么、反复出现的状态，其次才是城市、职业、口味这类硬信息。一次最多 3 条，且必须讲不同的事。
- **不记什么**：一次性的（今天几点、刚问的天气）、临时情绪、寒暄、任务执行结果；项目进度和任务状态、文件路径与工具名、以及称呼。「还差什么没做」这类几天就翻篇，留着只会让它说出过时的进度，实时进度有 `work_status` 可查；称呼归面板的「怎么叫你」，两边各存一份必然会打架（本机就撞过一次：记忆里写着「叫我小芯」，那是给机器人起的名字，却被记成了用户的称呼）。
- **怎么用**：下次提问时按相关性挑几条，分两组注入——「他这个人」和「手头在忙」。形态是一行短句串，不是带标签的逐条清单：**一张带标签的清单，最省力的用法就是照着念**，用户问「说说你对我的了解」，回答便退化成「长沙，手上两条线——…，还管我叫小芯」这种档案腔。同一件事的几种说法（「习惯用 Claude Code 干活」/「用 Claude Code 和 ESP32 做开发」）在注入时按共享专名合并，只留一条——它们的字面相似度只有 0.41，任何阈值都判不出重复，但说的就是一件事。
- **谁会看到**：这几条会随请求发给 DeepSeek，否则模型无从知道自己记得什么。不相关的记忆不会上传。面板顶部与记忆区都写了这一点。
- **删与关**：面板「它记得你」逐条列出，可单条忘记、整体清空；也可以直接对它说「忘掉香菜」。关掉开关后不再注入、不再抽取，记忆工具整组撤下，已有记忆不销毁。
- **敏感信息**：密码、验证码、证件号、银行卡、详细门址由 `looksSensitive()` 在写入前拦掉，不依赖提示词自觉——因为它一旦进文件，之后每次请求都会带上。

记忆是增强项，不是关键路径：抽取失败、超时、返回垃圾都静默跳过，不会影响已经完成的回复。

开发模式仅监听 `127.0.0.1:5173`；端口占用会报错。界面修改支持热更新，修改主进程／preload 后重启开发命令。这里不要运行公开绑定的开发服务器。

## 数据与恢复

真实个人数据：会话、待办、设置、计时。Electron 的 `userData` 目录下保存 `state-v1.json`；Windows 默认路径为 `%APPDATA%\芯伴\state-v1.json`（窗口位置在同目录的 `window-bounds-v1.json`，以 Electron 实际 `userData` 为准）。内部测试可以用 `XINBAN_DATA_DIR` 指定独立目录；日常使用不要设置。

- 主进程唯一写入、串行更新，临时文件写入并同步后 rename，保存成功才发布修改。
- 损坏、不兼容或不可读文件不被覆盖；进入只读安全模式，先退出应用并备份原文件，再人工修复／移走，不在错误提示中假装保存成功。
- 运行中的计时重启后进入「等待恢复」。按启动时系统时间估算剩余量，即使已经到期也要用户确认。运行期间使用单调时钟；若墙钟与单调时钟偏离 ≥ 5 秒（系统休眠或改时间），计时同样转「待确认」并提示原因，不会静默补算或继续扣时。真实合盖休眠与系统挂起事件尚未实测。
- 暂停计时保持暂停。已完成提醒不在每次启动时重播。
- 模拟任务、回放、摸摸与游戏不写入个人数据。模拟记录最多 30 个任务、40 条回放、512 个去重 ID；不是持久化审计系统。
- 模拟断开后显示状态待确认。重连清空陈旧任务、保留回放，需新建模拟任务；**不代表真实适配器快照同步已经实现**。
- 偏好页可导出个人 JSON 数据；清除必须通过原生确认对话框。导出不含模拟事件。可在偏好页导入之前导出的文件：只接受通过版本校验的 v1 数据，覆盖前必须经原生确认。清除不会删除已导出的文件。
- 模拟实验室另有「输入映射表」导出，内容是固定交互规格（长按阈值、去抖、A/B 动作与边界声明），不含个人数据或模拟事件，用于桌面与实体固件逐项对照。
- 宠物窗口位置单独保存在 `userData/window-bounds-v1.json`，不掺入个人数据导出。文件损坏或版本不兼容只回退默认位置，不进入个人数据的只读安全模式；恢复时只取坐标，窗口尺寸始终由代码决定。
- AI 凭据单独保存在 `userData/ai-credentials-v1.json`，API Key 经系统加密后落盘；系统加密不可用时拒绝保存，不降级明文。该文件不进入个人数据导出，清除凭据不影响待办与计时。AI 对话不写入任何文件。
- 长期记忆单独保存在 `userData/memory-v1.json`，同样不进入个人数据导出与回放文件。文件损坏或版本不认识时按「还没有记忆」处理，原文件保留不覆盖，应用照常启动。

## 安全与隐私边界

出站只有两处，都由你触发或显式开启：

- **DeepSeek**（`https://api.deepseek.com`，模型 `deepseek-flash`，Responses API 与 Search／Fetch 工具）：发送你主动输入的文字、这段对话的历史、工具执行结果、**与当前话题相关的几条长期记忆**、一行关系背景（「你们认识第 N 天」），以及正在进行的 agent 会话摘要（WorkBuddy；你在面板打开后还有 Claude Code / Codex）。
- **硅基流动**（可选，单独的 Key）：你按住麦克风时发送那段录音做转写；云端人声朗读时发送要念的文字；你在面板允许「看画面」并对单次请求按了 A 后，发送那几帧截屏/摄像头画面。

麦克风、摄像头、截屏全部默认关闭、需要在面板显式开启；没有键盘监听、没有遥测、没有开机自启。**主动开口不出站**：小屏上「Claude Code 在等你」「交周报到点了」这类话是本地事件触发、本地模板生成的；只有你按 A「细说」才会发起一次 AI 对话。关系账本（`bond-v1.json`）与提醒记录（`proactive-v1.json`）只存本机、不进导出。实体设备走 USB 串口、只传屏幕内容和按键事件，不出本机。

工具执行是本机行为，边界写在代码里而不是提示词里：文件路径必须解析到工作目录内——**默认是 `userData/workspace` 这个独立目录，不是应用自身**（早先默认应用目录，模型能改到自己的主进程代码），要作用在你的项目上用 `XINBAN_WORKSPACE` 指过去；拒绝绝对路径、`..`、NTFS 备用流、短文件名、设备名与链接逃逸；命令有白名单、超时与输出上限；写入前备份原文件。高风险工具逐次确认（见上）。**这不等于沙箱**。

Electron 启用 `sandbox`、`contextIsolation`，关闭 `nodeIntegration` 和 `webview`。preload 只暴露固定方法。IPC 校验来源窗口、顶层 frame URL、Zod 动作 schema。鼠标穿透通道只接受布尔值、只作用于伙伴窗口主 frame，不开放任意窗口控制。AI 对话 IPC 允许桌宠与面板两个应用窗口发起（仍逐次校验来源窗口与顶层 frame），凭据配置与清除只允许控制面板；出站端点限定 `api.deepseek.com`（模型、搜索、抓取各自校验），工具端点只允许 `/v1/tools/*`，Key 只经主进程使用，不回显、不进日志，错误信息也不含 Key 或响应体。来源链接只能用系统浏览器打开，且只接受 http／https、拒绝内嵌凭据。拒绝外部导航、弹窗、默认设备权限、下载和远程资源；生产模式不启动服务端口。

依赖审计当前为 0 漏洞。原先 9 个 moderate 来自开发工具链的 `minimatch`（经 ESLint／TypeScript-ESLint 传播），已用 `overrides` 固定到修复版 11.0.1，并重跑 lint／类型／单测／构建／E2E 确认 ESLint 未被破坏。这是跨主版本覆盖，升级 ESLint 时需重新评估。具体快照见实施清单。

## 当前限制

- 手动工作会话与模拟事件，不是 IDE、设计软件或文档软件自动接入。
- AI 对话已用真实 Key 验证：Responses 流式分块、工具循环（搜索 → 回填 → 结论）、应用 IPC 链路的增量一致性、「面板提问 → 桌宠小屏同步开口」、**真实联网搜索并展示来源**，以及**「告诉它我是谁 → 下一轮它答得出来」的记忆闭环**均通过。Key 只在运行时环境变量里传给测试，没有写入任何项目文件。硬件通信协议（USB 串口）已实现并用模拟设备自测，**真实 ESP32、串口在打包后 Electron 里的加载、参考固件均未实测**（见 `docs/hardware-protocol.md`）；没有 LVGL 或 ESP-IDF 工程。
- AI 支持流式输出、取消、用量与工具调用次数统计（仅内存，不做费用换算），以及通用、记忆、进度、派活与视觉各类工具（具体以 `src/core/agent.ts` 为准）。**没有**`web_search` 服务端内置工具（只有 `deepseek-v4-pro` 支持，当前用 flash 自建循环）。推理型模型的内部推理（`reasoning_content`）不显示、不保存。单步 60 秒、整轮 150 秒为请求上限，不是首字延迟保证。对话由主进程持有、两个窗口共享、退出即清空；跨会话留存的是记忆条目，不是聊天记录。
- 记忆的已知边界：抽取是尽力而为（失败静默跳过），偶尔会把「这周要交的材料」记成长期事实；相似度判重靠字面重合，换个说法可能记成两条；只做了本机单用户，没有多设备同步、没有加密存储（是普通 JSON 文件）、没有按时间衰减的自动清理。记忆文件里是明文——它不该放敏感信息，代码也会拦，但别把它当保险柜。
- 参考板图形仅为概念轮廓：未锁定模组、屏幕、尺寸、USB 布局、引脚与接线。
- 小游戏为窗口本地反应时间练习，无分数持久化；不是硬件延迟测试。
- 桌面按钮已实现短按／长按(800ms)／去抖(50ms)与可导出的输入映射表；模拟任务的「等待确认」可由 A 短按确认。实体 GPIO 时序、和弦按下、A 长按动作定义仍未验证。长按与去抖参数是原型交互规格，不是硬件测量结论。
- 鼠标穿透只覆盖窗口透明边距，依赖 Electron 的 `forward` 行为（Windows 已自动化验证，macOS 未验证）；位置恢复只按窗口中心点可见性回退，不做跨屏吸附、DPI 补偿或全屏自动勿扰。默认不置顶，也没有开机自启。
- v0.3 未实测项：官方钩子只用「真脚本 + 模拟的 Claude Code 事件」验证过，**没有在真实 Claude Code / Codex 会话里装过**；Codex 的 notify 参数格式来自文档摘要、未逐字核对。音乐桥只验证了「启动并读状态」，没有对网易云 / QQ 音乐实际切过歌（各客户端是否向系统报告播放状态因版本而异）。讲故事没有用真实 Key 跑过。物联网只在模拟中枢上跑通，固件未编译，Tasmota / Shelly / ESPHome 接口未对真设备验证，设备带 Web 密码时连不上。
- 没有安装包、签名、自动更新；性能目标、24 小时稳定性、实机效果均未验收。
- `play_audio` 的运行时播放器未在 Electron 实机／真实声卡上实测：格式支持取决于 Chromium 媒体栈（mp3/wav/ogg/m4a 等常见格式，不支持带 DRM 的内容）；本地文件会整段读进内存转成 `data:` URL，超大文件占内存；http(s) 链接依赖网络与对方允许直连；播放失败／结束通过服务订阅回报，界面暂无专门的播放状态面板，也没有独立的停止按钮。
